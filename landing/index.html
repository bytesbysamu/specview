Introducing Spec Doc

Your braindump becomes an engineering spec in minutes.

Write everything you know about a feature — raw and unfiltered. Spec Doc generates the structured documents your team needs to build it: analysis, epic, architecture, and an executor-ready implementation guide. No more blank-page paralysis. No more re-briefing the AI every session.

What Spec Doc generates

Analysis

analysis.md

The problem, distilled. Hard constraints, open questions, scope boundaries, and sequencing decisions — extracted from your raw notes. No fluff. No assumptions invented.

Epic

epic.md

Business value, task breakdown, effort estimates, dependencies, success criteria, and explicit non-goals. The contract between what you want and what gets built.

Architecture

architecture.md

System boundaries, component design, design decisions with rationale, technology stack, and execution flow. The long-lived document that outlives the sprint.

Implementation Guide

implementation-guide.md

Executor-ready instructions for every task: context, files to create or modify, implementation steps, test cases, commit plan, verification, and rollback. Hand directly to Claude Code.

How it works
1

Braindump

Write everything you know about the feature — raw, unfiltered, unstructured. Problems, constraints, prior art, open questions. The messier the better. Spec Doc handles the structure.

Every session I start on spec-doc, I spend 10–15 minutes re-establishing context. The chain adapter pattern. The SQLModel conventions. The Alembic rules. We need a Claude Code plugin that fixes this — bakes the conventions in, like financing-plugin did for Java.
2

Generate

One click. Spec Doc runs a three-step AI chain: analysis → epic → architecture. Each file appears on disk as it completes. You can read the analysis while the architecture is still generating.

✦ analysis ████████████ done ✦ epic ████████████ done ✦ architecture ████░░░░░░░░ generating… 3 files · claude-sonnet · 47s
3

Build

Open the implementation guide in Claude Code. Every task has concrete steps, real file paths, full test bodies, and a commit plan. No re-briefing. No context rebuilding. Just execute.

@claude-code-provider-plugin/chain-agent Implement Task 1: Reference Files Follow architecture.md §Component Design. Write flask-conventions.md first.

Analysis

Claude Code Provider Plugin — Analysis

Problem 1 — Raw CLI calls: providers/cli.py calls claude -p "<full system prompt + task>" as a subprocess. The full convention context is re-sent on every call — chain rules, Flask patterns, Angular idioms — as a raw string.

Problem 2 — Session context: Every spec-doc/specview session wastes 10–15 minutes re-establishing Flask/Angular conventions that a Claude agent should already know.

Backend Provider Interface (Primary Scope): The plugin installs as a proper Claude Code plugin (financing-plugin layout: agents/, skills/, references/, hooks/). The backend's providers/cli.py gains a structured call mode: claude --agent chain-agent -p "<task>".

"

The agent that loads chain-conventions.md before writing a workflow step cannot bypass the adapter boundary, because the rule is in its context — not its memory.

From the Claude Code Provider Plugin epic
"

Encode conventions once into reference files so Claude never re-establishes context and never generates a pattern violation.

Spec Doc value proposition
Self-host in minutes
1

Clone

Clone the repo and copy the override template.

git clone https://github.com/bytesbysamu/specview cd specview cp docker-compose.override.example.yml \ docker-compose.override.yml
2

Configure

Mount your Claude credentials. Set your database URL and JWT secret.

api: environment: CHAIN_PROVIDER: cli volumes: - ~/.claude:/home/appuser/.claude - ~/.claude-openclaw:/home/appuser/.claude-openclaw
3

Run

Build and start. Open the app at localhost:8095.

docker compose build docker compose up -d # Open http://localhost:8095
