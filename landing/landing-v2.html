Component Design & Boundaries

The chain adapter is the single AI call boundary. Feature modules import only from chain/adapter.py and never reach into provider implementations directly — this keeps the provider swappable without touching any feature code.

Flask blueprints are registered with a versioned prefix, services own all transaction boundaries, and background jobs are coordinated through a module-level state dict so route handlers remain stateless.

Data Flow

Every spec generation request follows a single path: route → service → chain adapter → provider. The route validates auth, the service owns the transaction, the adapter calls the model.

Questions
What do I need to use Specview?

A browser. Sign up, paste a braindump, click generate. The hosted version runs everything — no CLI, no local setup, no API key required.

Is this like Lovable or Bolt?

No. Lovable generates code from prompts. Specview generates specs from braindumps. You review the architecture before any code is written. The specs become the documentation — they don't disappear after deploy.

What if the generated specs are wrong?

Edit the braindump and regenerate. Or edit the markdown directly. The specs are files you own — not locked in a platform. Wrong architecture before you build beats wrong code after you ship.

Can I self-host?

Yes. Specview is open-source. git clone, docker compose up, done. The hosted version at app.specview.io saves you the setup and keeps you on the latest model.

Why $29/month?

Unlimited spec generation. No credits. No per-request charges. Kiro costs $20–550/month in credits. Cursor is $20/month for code suggestions. $29/month for full architecture documents that your whole team reads is a different category of value.
