How it works
The Methodology

Three passes from raw thought to a shippable task list.

No templates, no prompts to fill in. Write what you know and let the pipeline do the analytical work that usually takes a day of meetings.

1

Braindump

Write everything you know — constraints, hunches, prior art, open questions — exactly as it comes out of your head, without editing for clarity or completeness.

2

Spec Set

Five analytical passes run in sequence — analysis, epic, architecture, timeline, and implementation guide — each document grounded in the one before it.

3

Implementation

The implementation guide hands each task to a coding agent with exact steps, target files, and verify criteria so the work ships without ambiguity or back-and-forth.

Component Design & Boundaries

The chain adapter is the single AI call boundary. Feature modules import only from chain/adapter.py and never reach into provider implementations directly — this keeps the provider swappable without touching any feature code.

Flask blueprints are registered with a versioned prefix, services own all transaction boundaries, and background jobs are coordinated through a module-level state dict so route handlers remain stateless.
