# Task 2: Generate `flask/dto.py`

## 1. Context

This task creates the Pydantic DTO layer that `test_contract.py` will use as its primary assertion mechanism. It does two things in order: authors `flask/openapi.yaml` from the prose contract in `flask/api-contract.md`, then runs `datamodel-codegen` to produce `flask/dto.py` from that schema. Both files are committed as first-class artifacts. The DTOs matter because a Flask response that cannot deserialize into the correct model raises a `ValidationError` naming the offending field — a more informative failure than a generic assertion error. This capability has 14 Phase 1 routes (verified from `flask/api-contract.md`) and 11 named response/request schemas.

**Trade-offs considered:**
- Hand-authoring `flask/dto.py` directly — rejected because hand-authored models can silently drift from the spec; generated models are provably in sync with `openapi.yaml`
- Reusing the existing `flask/modules/context/dto.py` models — rejected because those are module-internal request/response types bound to route handlers; `flask/dto.py` is a separate contract-validation layer with different naming and solely consumed by tests
- Generating in CI on every run — rejected because this would couple CI to `datamodel-codegen` being installed and would require `openapi.yaml` to be stable before any test can run; the "commit once" approach matches the capture-once philosophy established in the architecture

## 5. Tests

Complete file — `flask/tests/test_dto.py`:

```python
"""Tests for generated flask/dto.py — DTO deserialization and shape invariants.

Run: python -m pytest flask/tests/test_dto.py -v

Deviations from guide:
- If codegen produces different class names, update imports here and note in commit body.
"""
from __future__ import annotations

import sys
from pathlib import Path

import pytest
from pydantic import ValidationError

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))

from dto import (
    ContextFileResponse,
    ErrorResponse,
    HealthResponse,
    ProjectCreated,
    ProjectDetail,
    ProjectSummary,
    SpecDetail,
    SpecSummary,
    SuccessResponse,
)


# ---------------------------------------------------------------------------
# HealthResponse
# ---------------------------------------------------------------------------

def test_health_response_valid():
    m = HealthResponse(status="ok")
    assert m.status == "ok"


def test_health_response_missing_status_raises():
    with pytest.raises(ValidationError) as exc_info:
        HealthResponse()
    assert "status" in str(exc_info.value), "ValidationError must name the missing field"


# ---------------------------------------------------------------------------
# ContextFileResponse
# ---------------------------------------------------------------------------

def test_context_file_response_valid():
    m = ContextFileResponse(content="# Hello", exists=True)
    assert m.content == "# Hello"
    assert m.exists is True


def test_context_file_response_empty_content_is_valid():
    # exists logic is computed by the route, not the DTO; empty string is a valid payload
    m = ContextFileResponse(content="", exists=False)
    assert m.exists is False


def test_context_file_response_missing_content_raises():
    with pytest.raises(ValidationError) as exc_info:
        ContextFileResponse(exists=True)
    assert "content" in str(exc_info.value)


def test_context_file_response_missing_exists_raises():
    with pytest.raises(ValidationError) as exc_info:
        ContextFileResponse(content="x")
    assert "exists" in str(exc_info.value)


# ---------------------------------------------------------------------------
# SuccessResponse
# ---------------------------------------------------------------------------

def test_success_response_true():
    m = SuccessResponse(success=True)
    assert m.success is True


def test_success_response_false():
    m = SuccessResponse(success=False)
    assert m.success is False


def test_success_response_missing_success_raises():
    with pytest.raises(ValidationError):
        SuccessResponse()


# ---------------------------------------------------------------------------
# SpecSummary vs SpecDetail — structural invariant
# ---------------------------------------------------------------------------

def test_spec_summary_has_no_content_field():
    m = SpecSummary(filename="epic.md", label="Epic")
    assert "content" not in m.model_fields, (
        "SpecSummary must not expose a content field — list endpoint does not return content"
    )


def test_spec_detail_has_content_field():
    m = SpecDetail(filename="epic.md", label="Epic", content="# Epic")
    assert m.content == "# Epic"
    assert "content" in m.model_fields


def test_spec_detail_missing_content_raises():
    with pytest.raises(ValidationError):
        SpecDetail(filename="epic.md", label="Epic")


# ---------------------------------------------------------------------------
# ProjectSummary
# ---------------------------------------------------------------------------

def test_project_summary_valid():
    m = ProjectSummary(
        id="my-project-1700000000000",
        name="My Project",
        createdAt="2024-01-15T10:00:00.000Z",
        specs=[{"filename": "epic.md", "label": "Epic"}],
    )
    assert m.id == "my-project-1700000000000"
    assert len(m.specs) == 1


def test_project_summary_specs_are_spec_summary_instances():
    m = ProjectSummary(
        id="x",
        name="X",
        createdAt="2024-01-01T00:00:00.000Z",
        specs=[{"filename": "epic.md", "label": "Epic"}],
    )
    assert isinstance(m.specs[0], SpecSummary), (
        "ProjectSummary.specs items must deserialize as SpecSummary"
    )


def test_project_summary_missing_id_raises():
    with pytest.raises(ValidationError):
        ProjectSummary(
            name="X",
            createdAt="2024-01-01T00:00:00.000Z",
            specs=[],
        )


# ---------------------------------------------------------------------------
# ProjectDetail
# ---------------------------------------------------------------------------

def test_project_detail_specs_are_spec_detail_instances():
    m = ProjectDetail(
        id="my-project-1700000000000",
        name="My Project",
        createdAt="2024-01-15T10:00:00.000Z",
        specs=[{"filename": "epic.md", "label": "Epic", "content": "# Epic"}],
    )
    assert isinstance(m.specs[0], SpecDetail)
    assert m.specs[0].content == "# Epic"


def test_project_detail_missing_specs_raises():
    with pytest.raises(ValidationError):
        ProjectDetail(id="x", name="x", createdAt="2024-01-01T00:00:00.000Z")


# ---------------------------------------------------------------------------
# ProjectCreated
# ---------------------------------------------------------------------------

def test_project_created_has_exactly_three_fields():
    m = ProjectCreated(
        id="my-project-1700000000000",
        name="My Project",
        createdAt="2024-01-15T10:00:00.000Z",
    )
    assert set(m.model_fields.keys()) == {"id", "name", "createdAt"}, (
        "ProjectCreated must have exactly id, name, createdAt — POST /api/projects response shape"
    )


# ---------------------------------------------------------------------------
# ErrorResponse
# ---------------------------------------------------------------------------

def test_error_response_valid():
    m = ErrorResponse(error="Project not found")
    assert m.error == "Project not found"


def test_error_response_missing_error_raises():
    with pytest.raises(ValidationError):
        ErrorResponse()
```

## 9. Deviations Allowed

- **Codegen produces different class names** (e.g. `ContextFile` instead of `ContextFileResponse`): inspect `flask/dto.py`, update all imports in `flask/tests/test_dto.py` to match, note the divergence in the commit body under `Deviations:`. Do not rename the generated classes — treat the codegen output as authoritative.
- **Codegen adds `Optional[...]` wrapping on non-required fields**: accept as-is; it is correct Pydantic v2 behavior for optional schema properties.
- **`List[T]` vs `list[T]`**: codegen version determines this; both are valid Pydantic v2; tests do not assert on the annotation type, only on runtime behavior.
- **`description:` lines missing from path items** cause no functional difference in codegen output; the pattern above omits them for brevity on non-required paths. Add them if a linter requires it.
- **`pyyaml` not installed** for the YAML parse verification: `pip install pyyaml` is a one-liner verification aid, not a project dependency; skip the verify command if preferred and proceed to the codegen run directly.
- **Side-effect required** (push, publish, schema migration): STOP, mark `[REQUIRES APPROVAL]`, and ask.

## 10. Out of Scope

This task produces the DTO layer and its unit tests. It does not wire those DTOs into any live HTTP calls or test Flask's actual running server. The remaining integration-test capability tasks are deferred because they depend on infrastructure (`capture.py`, `fixtures/`, `test_contract.py`) that doesn't yet exist and whose scope is deliberately staged to keep each task independently revertible.

- `flask/tests/capture.py` — one-time Express fixture script; deferred until Flask routes are fully stable; requires Express live on 3100
- `flask/tests/fixtures/` — committed fixture JSON; deferred because it depends on `capture.py` running successfully
- `flask/tests/test_contract.py` — the integration suite; deferred because it depends on both `flask/dto.py` (this task) and `fixtures/` (capture task); it is the primary consumer of the DTOs produced here
- Pydantic request validation in Flask route handlers — explicitly out of scope per architecture decision table; no untrusted external consumers exist yet
- Regenerating `dto.py` on `openapi.yaml` change — no CI trigger exists; if `openapi.yaml` is updated, re-run Step 3 manually and commit the updated `dto.py`

**Rule for the executor**: if a change appears helpful but is listed here, STOP and flag it as a deviation rather than expanding this task's blast radius.
