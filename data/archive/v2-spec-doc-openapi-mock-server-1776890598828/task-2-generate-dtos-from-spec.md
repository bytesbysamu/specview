# Task 2: Generate DTOs from openapi.yaml

## 1. Context

This task converts `flask/openapi.yaml` (produced by Task 1) into a `flask/dtos/` Python package containing Pydantic v2 models generated by `datamodel-codegen`. The generated models become the shared serialization contract that `mock_server.py` (Task 3) uses for response construction — eliminating the class of silent drift where mock and production describe the same shape in incompatible ways. This is a one-time derivation step: the spec is written once, the models follow, and neither consumer invents its own schema definition.

**Trade-offs considered:**
- **Hand-authoring Pydantic models in `flask/dtos/`** — rejected because it recreates the exact duplication problem the architecture exists to prevent; field names and types would diverge from `openapi.yaml` on the first update.
- **Using `flask/modules/context/dto.py` as the DTO layer** — rejected because it covers only context shapes, was written before this epic, and scoping it to the full spec would require replacing it rather than augmenting it; the generated module is additive and does not touch existing routes.
- **Code generation committed as a static artifact** — preferred because the generated file is stable between spec updates, requires no runtime codegen dependency, and is reviewable as a diff when the spec changes.

### Step 3: Generate flask/dtos/models.py from openapi.yaml

**Action**: Run `datamodel-codegen` against `flask/openapi.yaml` to produce `flask/dtos/models.py`. Use `pydantic_v2.BaseModel` as the output model type to match the Pydantic v2 patterns already in use in `flask/modules/context/dto.py` (`.model_dump()`, `.model_validate()`). Do NOT pass `--snake-case-field` — field names must match the JSON keys in the OpenAPI spec verbatim (e.g., `createdAt` stays `createdAt`), because `mock_server.py` and the Angular frontend consume these as-is.

**File**: `flask/dtos/models.py` (new, generated — do not hand-author)

**Pattern**:
```bash
# Run from {WORKSPACE}/spec-doc/
datamodel-codegen \
  --input flask/openapi.yaml \
  --input-file-type openapi \
  --output flask/dtos/models.py \
  --output-model-type pydantic_v2.BaseModel
```

**Expected output shape** (names will reflect the actual schema names in openapi.yaml — adapt accordingly):
```python
# generated by datamodel-codegen:
#   filename:  openapi.yaml
#   timestamp: 2026-...

from __future__ import annotations
from typing import List, Optional
from pydantic import BaseModel


class File(BaseModel):
    filename: str
    label: str
    content: Optional[str] = None


class Project(BaseModel):
    id: str
    name: str
    createdAt: str
    specs: List[File]


class ContextEntry(BaseModel):
    content: str
    exists: bool

# ... additional models per schemas in openapi.yaml
```

**Verify**: `python -c "from dtos.models import *; print('ok')"` from the `flask/` directory prints `ok` with no import errors.

### Step 5: Verify dtos are importable and cover the full spec

**Action**: Manually confirm each schema object in `flask/openapi.yaml` under `components/schemas` has a corresponding class in `flask/dtos/models.py`. This is a human pre-test verification step before running the automated test suite.

**File**: terminal

**Pattern**:
```bash
# List schemas in the spec
python -c "
import yaml, pathlib
spec = yaml.safe_load(pathlib.Path('flask/openapi.yaml').read_text())
print(list(spec.get('components', {}).get('schemas', {}).keys()))
"

# Confirm matching classes exist in generated models
python -c "
import dtos.models as m
import yaml, pathlib
spec = yaml.safe_load(pathlib.Path('flask/openapi.yaml').read_text())

print('MISSING:', missing) if missing else print('ALL PRESENT')

```

**Verify**: Second command prints `ALL PRESENT`. If any schema is missing, the codegen run in Step 3 had an error — re-examine the openapi.yaml and rerun datamodel-codegen.

## 5. Tests

**Framework**: `pytest` with plain `assert` statements — matching `flask/tests/test_project.py` and `flask/tests/test_context_files.py` conventions. No `unittest.TestCase`, no `assert_*` helper calls.

**File**: `flask/tests/test_dtos.py` (new)

```python
"""Tests for flask/dtos/ — generated Pydantic models from openapi.yaml.

Run: python -m pytest flask/tests/test_dtos.py -v

Validates:
  - Every schema in openapi.yaml has a corresponding generated class (structural)
  - Core models instantiate with valid data and model_dump() returns expected keys
  - Required fields raise ValidationError when absent
  - Generated models use Pydantic v2 API (.model_dump, .model_validate)
"""
from __future__ import annotations

import pathlib
import sys

import pytest
import yaml

# Ensure flask/ is on the path regardless of where pytest is invoked from
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent.parent))


# ---------------------------------------------------------------------------
# Helpers
# ---------------------------------------------------------------------------

def _openapi_schema_names() -> set[str]:
    """Parse openapi.yaml and return the set of component schema names."""
    openapi_path = pathlib.Path(__file__).resolve().parent.parent / "openapi.yaml"
    assert openapi_path.exists(), (
        f"openapi.yaml not found at {openapi_path} — Task 1 prerequisite not met"
    )
    spec = yaml.safe_load(openapi_path.read_text())
    names = set(spec.get("components", {}).get("schemas", {}).keys())
    assert names, "openapi.yaml has no schemas in components/schemas — spec may be incomplete"
    return names


# ---------------------------------------------------------------------------
# Structural: schema coverage
# ---------------------------------------------------------------------------

def test_all_openapi_schemas_have_generated_models():
    """Every schema in openapi.yaml components/schemas must be a class in dtos.models."""
    import dtos.models as models_module

    schema_names = _openapi_schema_names()
    missing = [name for name in sorted(schema_names) if not hasattr(models_module, name)]
    assert missing == [], (
        f"Schemas in openapi.yaml with no generated class in dtos/models.py: {missing}. "
        "Re-run datamodel-codegen to regenerate."
    )


def test_generated_models_are_pydantic_v2():
    """Generated models must use Pydantic v2 BaseModel (has model_dump, model_validate)."""
    import dtos.models as models_module
    from pydantic import BaseModel

    schema_names = _openapi_schema_names()
    for name in schema_names:
        cls = getattr(models_module, name, None)
        if cls is None:
            continue  # covered by test_all_openapi_schemas_have_generated_models
        assert issubclass(cls, BaseModel), (
            f"dtos.models.{name} is not a Pydantic BaseModel subclass — "
            "ensure --output-model-type pydantic_v2.BaseModel was passed to datamodel-codegen"
        )
        assert hasattr(cls, "model_dump"), (
            f"dtos.models.{name} lacks model_dump — Pydantic v2 required"
        )
        assert hasattr(cls, "model_validate"), (
            f"dtos.models.{name} lacks model_validate — Pydantic v2 required"
        )


# ---------------------------------------------------------------------------
# Behavioral: Project model
# NOTE: field names below must match the actual openapi.yaml Project schema.
# If Task 1 used different field names, update these tests to match.
# ---------------------------------------------------------------------------

def test_project_model_instantiates_with_valid_data():
    """Project model accepts valid fields and model_dump() returns them."""
    from dtos.models import Project

    project = Project(
        id="my-project-1700000000000",
        name="My Project",
        createdAt="2024-01-15T10:00:00.000Z",
        specs=[],
    )
    data = project.model_dump()
    assert data["id"] == "my-project-1700000000000", "id field missing from model_dump output"
    assert data["name"] == "My Project", "name field missing from model_dump output"
    assert data["createdAt"] == "2024-01-15T10:00:00.000Z", "createdAt field missing"
    assert data["specs"] == [], "specs field must be an empty list when no specs provided"


def test_project_model_required_fields():
    """Project model raises ValidationError when required fields are absent."""
    from dtos.models import Project
    from pydantic import ValidationError

    with pytest.raises(ValidationError) as exc_info:
        Project(name="No ID Project", createdAt="2024-01-15T10:00:00.000Z", specs=[])
    errors = exc_info.value.errors()
    field_names = [e["loc"][0] for e in errors]
    assert "id" in field_names, f"Expected ValidationError for missing 'id', got errors: {errors}"


# ---------------------------------------------------------------------------
# Behavioral: ContextEntry model
# NOTE: if Task 1 named this schema differently (e.g., ContextResponse),
# update the import below to match.
# ---------------------------------------------------------------------------

def test_context_entry_model_with_content():
    """ContextEntry with content instantiates correctly and exists=True."""
    from dtos.models import ContextEntry

    entry = ContextEntry(content="# Builder context", exists=True)
    data = entry.model_dump()
    assert data["content"] == "# Builder context", "content field missing"
    assert data["exists"] is True, "exists field must be True"


def test_context_entry_model_empty():
    """ContextEntry with empty content instantiates correctly and exists=False."""
    from dtos.models import ContextEntry

    entry = ContextEntry(content="", exists=False)
    data = entry.model_dump()
    assert data["content"] == "", "content must be empty string, not None or absent"
    assert data["exists"] is False, "exists must be False for empty content"


def test_context_entry_required_fields():
    """ContextEntry raises ValidationError when content is missing."""
    from dtos.models import ContextEntry
    from pydantic import ValidationError

    with pytest.raises(ValidationError) as exc_info:
        ContextEntry(exists=True)
    errors = exc_info.value.errors()
    field_names = [e["loc"][0] for e in errors]
    assert "content" in field_names, (
        f"Expected ValidationError for missing 'content', got errors: {errors}"
    )


# ---------------------------------------------------------------------------
# Behavioral: SuccessResponse model (used by mock for mutation responses)
# NOTE: if Task 1 named this schema differently (e.g., OperationResult),
# update the import below to match.
# ---------------------------------------------------------------------------

def test_success_response_model_true():
    """SuccessResponse with success=True serializes correctly."""
    from dtos.models import SuccessResponse

    resp = SuccessResponse(success=True)
    data = resp.model_dump()
    assert data["success"] is True, "success field must be True"


def test_success_response_model_false():
    """SuccessResponse with success=False serializes correctly."""
    from dtos.models import SuccessResponse

    resp = SuccessResponse(success=False)
    data = resp.model_dump()
    assert data["success"] is False, "success field must serialize as False, not absent"


# ---------------------------------------------------------------------------
# Behavioral: model_validate round-trip
# ---------------------------------------------------------------------------

def test_project_model_validate_from_dict():
    """Project.model_validate() accepts a plain dict (as mock_server.py will use it)."""
    from dtos.models import Project

    raw = {
        "id": "test-1700000000000",
        "name": "Test Project",
        "createdAt": "2024-06-01T00:00:00.000Z",
        "specs": [],
    }
    project = Project.model_validate(raw)
    assert project.id == "test-1700000000000", "model_validate must populate id from dict"
    assert project.name == "Test Project", "model_validate must populate name from dict"
```

## 9. Deviations Allowed

- **Schema names in `openapi.yaml` differ from `Project`/`ContextEntry`/`SuccessResponse`** — update import names in the behavioral tests (`test_dtos.py`) to match; the structural test (`test_all_openapi_schemas_have_generated_models`) is already schema-name-agnostic and requires no change.
- **`datamodel-codegen` produces `Optional[str]` instead of `str` for a field you expect required** — the openapi.yaml schema may have that field marked `nullable: true` or absent from `required:`; fix in the spec (Task 1's artifact), then re-run codegen; do not hand-edit `models.py`.
- **Test framework mismatch** — all existing tests use plain `assert` statements; translate silently and note in commit body.
- **Side-effect required** (push, publish, schema change) — STOP, mark [REQUIRES APPROVAL] and ask.
- **Step N reveals openapi.yaml is missing a schema** — STOP on this task; flag the gap to the spec author for Task 1 correction before continuing.

## 10. Out of Scope

This task produces a static generated artifact and its tests. It does not wire the generated models into any live code path. The existing `flask/modules/context/dto.py` is left untouched — its replacement by the generated models is a future concern once Tasks 2 and 3 have validated the generated shapes against the full Angular frontend. The `dtos` package will be imported for the first time by `mock_server.py` in Task 3; that import is that task's responsibility.

- **Replacing `flask/modules/context/dto.py` with generated models** — deferred; the context routes are in production and the replacement requires route-level testing; revisit when Tasks 2 and 3 land
- **CI integration for codegen** — deferred per architecture decision ("DTO generation as a CI step: No pipeline consumer exists"); revisit when the Flask routes from Tasks 2 and 3 require repeatable builds
- **Adding `datamodel-code-generator` to `requirements.txt`** — not a runtime dependency; regeneration is a manual workflow; include only when a CI step is in scope
- **`mock_server.py` importing from `dtos`** — Task 3's responsibility; this task only produces the importable artifact
- **Swagger UI or openapi.yaml serving** — explicitly excluded by the architecture; no named consumer at this stage
