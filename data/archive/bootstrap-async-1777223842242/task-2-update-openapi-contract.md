# Task 2: Update OpenAPI Contract — Implementation Guide

**Purpose**: Replace the synchronous `POST /api/ai/text/bootstrap-project` contract (200 + `BootstrapProjectResponse`) with an async job contract (202 + `BootstrapStartResponse`), add the polling endpoint `GET /api/ai/text/bootstrap-project/status/{job_id}`, define the `BootstrapJobStatus` schema mirroring `GenerateTaskStatusResponse`, and regenerate `dtos/models.py`.

**Effort**: 0.5 days

**Dependencies**: None — pure contract + codegen; no route handlers required.

**Parallel With**: T1 (workflow definition lives in `modules/ai/`; no file overlap with `openapi.yaml` or `dtos/`)

**Blocks**: T3 (Flask route handlers import the new DTOs), T4 (Angular service types flow from the generated contract)

**Related**:
- [Solution Architecture](./architecture.md)
- [Epic](./epic.md)

---

## 1. Context

The existing `POST /api/ai/text/bootstrap-project` returns 200 only after holding the HTTP connection for the full chain duration (10–25 min). No infra-level timeout tuning fixes this — the held connection is the structural failure. This task lays the contract foundation for the async fix: the POST acknowledges in milliseconds with a `job_id`; a new status endpoint lets the client poll until the job resolves. The `BootstrapJobStatus` shape is deliberately parallel to `GenerateTaskStatusResponse` (the proven `task_gen` shape) so the Angular polling client, DTOs, and test patterns can all port from the prior consumer rather than being invented.

**Trade-offs considered**:
- **Add a `job_id` field to the existing 200 response** — rejected; a 200 carrying a `job_id` is semantically misleading (the work is not done) and forces T3 to branch on the presence of that field, adding runtime complexity with no benefit.
- **Define `BootstrapJobStatus` independently of `GenerateTaskStatusResponse`** — rejected; the schemas serve the same polling pattern. Mirroring field names (`running`, `done`, `error`) means the Angular polling loop is structurally identical to the `task_gen` one, and test assertions transfer directly.
- **Change the POST response to 202 + new schema; add a parallel status path** — preferred; correct HTTP semantics, no ambiguity for the client, and the `task_gen` precedent means every downstream artifact (DTOs, routes, Angular client) has a working template to port from.

### Step 1: Update `openapi.yaml` — all contract changes

**Action**: Make four targeted edits to `openapi.yaml` in a single editing pass:
1. Change the POST `/api/ai/text/bootstrap-project` response from `'200'` / `BootstrapProjectResponse` to `'202'` / `BootstrapStartResponse`.
2. Add the `GET /api/ai/text/bootstrap-project/status/{job_id}` path block immediately after the POST block.
3. Add `BootstrapStartResponse` schema to `components/schemas`.
4. Add `BootstrapJobStatus` schema to `components/schemas`, referencing the existing `BootstrapFile` schema.

**File**: `spec-doc/api/openapi.yaml` (CODEBASE CONTEXT — 988 lines, existing file)

**Edit 1 of 4 — POST response (find the existing `'200'` block under `/api/ai/text/bootstrap-project`)**:

Replace:
```yaml
      responses:
        '200':
          description: Bootstrap files generated synchronously.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BootstrapProjectResponse'
```
With:
```yaml
      responses:
        '202':
          description: Bootstrap job accepted; poll GET .../status/{job_id} for result.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BootstrapStartResponse'
        '422':
          $ref: '#/components/responses/BadRequest'
        '500':
          $ref: '#/components/responses/InternalError'
```

> The exact description text on the existing `'200'` line may differ slightly — match by `$ref: '#/components/schemas/BootstrapProjectResponse'` as the unambiguous anchor.

**Edit 2 of 4 — Add GET status path (insert immediately after the POST block's closing line, before the next top-level path key)**:

```yaml
  /api/ai/text/bootstrap-project/status/{job_id}:
    get:
      summary: Poll bootstrap job status
      operationId: getBootstrapProjectStatus
      tags:
        - ai
      parameters:
        - name: job_id
          in: path
          required: true
          schema:
            type: string
            format: uuid
          description: Job identifier returned by POST /api/ai/text/bootstrap-project.
      responses:
        '200':
          description: Current status of the bootstrap job.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BootstrapJobStatus'
        '404':
          $ref: '#/components/responses/NotFound'
        '500':
          $ref: '#/components/responses/InternalError'
```

**Edit 3 of 4 — Add `BootstrapStartResponse` schema (insert into `components/schemas`, near the existing `BootstrapProjectResponse` block at ~line 851)**:

```yaml
    BootstrapStartResponse:
      type: object
      description: Immediate 202 acknowledgement from POST bootstrap-project.
      required:
        - job_id
      properties:
        job_id:
          type: string
          format: uuid
          description: >-
            Opaque job identifier. Pass to GET .../status/{job_id} to poll for
            completion. The job is evicted from the server on the first terminal
            (done=true) read.
```

**Edit 4 of 4 — Add `BootstrapJobStatus` schema (insert into `components/schemas`, adjacent to `BootstrapStartResponse`)**:

```yaml
    BootstrapJobStatus:
      type: object
      description: >-
        Status snapshot returned by GET bootstrap-project/status/{job_id}.
        Mirrors GenerateTaskStatusResponse shape for Angular polling parity.
      required:
        - running
        - done
      properties:
        running:
          type: boolean
          description: True while the background chain is in progress.
        done:
          type: boolean
          description: True once the job has terminated (successfully or not).
        files:
          type: array
          items:
            $ref: '#/components/schemas/BootstrapFile'
          description: >-
            Output files produced by the bootstrap run. Present only when
            done is true and no error occurred.
        error:
          type: string
          description: >-
            Error message captured from the background job. Present only
            when done is true and the job failed.
        latencyMs:
          type: integer
          minimum: 0
          description: >-
            Wall-clock milliseconds from job start to completion. Present
            only when done is true.
```

```python
class TestBootstrapAsyncContract:
    """Validates the async bootstrap job contract added in bootstrap-async epic."""

    def test_post_bootstrap_returns_202(self, spec):
        post = spec["paths"]["/api/ai/text/bootstrap-project"]["post"]["responses"]
```

```python
class TestBootstrapAsyncDTOs:
    """Validates generated Pydantic v2 classes for the async bootstrap contract."""

    def test_bootstrap_start_response_valid(self):
        import uuid
        job_id = str(uuid.uuid4())
        r = BootstrapStartResponse(job_id=job_id)
        assert r.job_id == job_id

    def test_bootstrap_start_response_missing_job_id_raises(self):
        with pytest.raises(ValidationError) as exc_info:
            BootstrapStartResponse()
        errors = exc_info.value.errors()
        fields = [e["loc"][0] for e in errors]
        assert "job_id" in fields

    def test_bootstrap_job_status_running_state(self):
        s = BootstrapJobStatus(running=True, done=False)
        assert s.running is True
        assert s.done is False
        # Optional fields absent
        assert s.files is None
        assert s.error is None

    def test_bootstrap_job_status_done_with_files(self):
        s = BootstrapJobStatus(
            running=False,
            done=True,
            files=[BootstrapFile(filename="analysis.md", content="# Analysis")],
            latency_ms=8500,   # snake_case; adjust to latencyMs if generator preserves camelCase
        )
        assert s.done is True
        assert s.running is False
        assert len(s.files) == 1
        assert s.files[0].filename == "analysis.md"
        assert s.latency_ms == 8500  # adjust field name to match generated output

    def test_bootstrap_job_status_done_with_error(self):
        s = BootstrapJobStatus(running=False, done=True, error="chain timed out")
        assert s.done is True
        assert s.error == "chain timed out"
        assert s.files is None

    def test_bootstrap_job_status_missing_required_raises(self):
        with pytest.raises(ValidationError) as exc_info:
            BootstrapJobStatus(running=True)  # done is required
        errors = exc_info.value.errors()
        fields = [e["loc"][0] for e in errors]
        assert "done" in fields

    def test_bootstrap_file_unchanged(self):
        """Guard: BootstrapFile must still have filename + content (T3 depends on it)."""
        f = BootstrapFile(filename="epic.md", content="# Epic")
        assert f.filename == "epic.md"
        assert f.content == "# Epic"
```

## 10. Out of Scope

This task covers only the OpenAPI contract surface and the generated DTOs. It does not touch Flask route handlers, Angular service code, or any workflow/chain logic. The contract must be complete and valid before those downstream artifacts can be built; that is the sole purpose of this task.

- **Flask route handlers for the async POST and GET status endpoints** — T3's scope; `everyOpenapiPath_hasRouteHandler` failing is the explicit signal that T3 is still outstanding
- **Angular `ai.service.ts` (`startBootstrapProject`, `getBootstrapStatus`) and polling loop in `new-project.component.ts`** — T4's scope; depends on T3 completing first
- **`BootstrapProjectResponse` schema removal** — the schema is still referenced by `/api/spec-gen/generate`; it must not be removed in this task; any cleanup is a separate housekeeping task after the spec-gen endpoint is audited
- **`BOOTSTRAP_WORKFLOW` definition** — T1's scope; no overlap with this task's files
- **SSE progress streaming for `partial` field on `BootstrapJobStatus`** — deferred to the `braindump-streaming-task-gen` epic; the `BootstrapJobStatus` schema intentionally omits `partial` until that epic lands
- **`latencyMs` minimum enforcement on the Flask side** — the `minimum: 0` constraint is declared in the schema and enforced by the DTO; backend runtime enforcement is T3's concern
