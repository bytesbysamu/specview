# Task Fix: SQLite Capacitor Config

**Purpose**: Add the missing `CapacitorSQLite` plugin configuration to `capacitor.config.ts` so the Capacitor runtime knows where to store the SQLite database on iOS. Without this config block, the plugin cannot create or locate database files, causing all SQLite operations to fail silently or throw on native.

**Effort**: 15 minutes

**Dependencies**: None (config-only change, no code changes)

**Parallel With**: --

**Blocks**: All SQLite-dependent features (Check-In sessions, draft persistence, trends, history) are broken on iOS until this lands.

## 4. Root Cause Analysis

The `SqliteService` was ported faithfully from howDays' pattern. The service code is correct -- it dynamically imports `@capacitor-community/sqlite`, uses `addUpgradeStatement`, `createConnection`, `open`, `query`, and `run` exactly as howDays does. The `CheckinDataService` consumer is also correct.

The failure is in Capacitor's configuration layer. The `@capacitor-community/sqlite` plugin requires three config values to operate on iOS:

1. **`iosDatabaseLocation`** -- tells the plugin where under the app sandbox to store `.db` files. Without this, the plugin does not know where to write and either fails to create the database or stores it in an unpredictable location.
2. **`iosIsEncryption`** -- must be explicitly `false` unless you've set up SQLCipher. If omitted, the plugin may attempt encryption setup and fail.
3. **`androidIsEncryption`** -- same for Android.

howDays has this config. Constellation's reference config (already in the Bubls repo at `/projects/bubls/reference/constellation-capacitor.config.ts`) has this config. Bubls does not.

The Podfile confirms the native pod `CapacitorCommunitySqlite` is already installed. The npm package `@capacitor-community/sqlite` is already in `package.json`. The only missing piece is the three-line plugin config block.

## 5. Fix Implementation

### File to Modify

**`/projects/bubls/capacitor.config.ts`**

Current state (lines 10-16):
```typescript
  plugins: {
    SplashScreen: {
      launchAutoHide: false,
      backgroundColor: '#0a0a0a',
      showSpinner: false,
    },
  },
```

Target state:
```typescript
  plugins: {
    CapacitorSQLite: {
      iosDatabaseLocation: 'Library/CapacitorDatabase',
      iosIsEncryption: false,
      androidIsEncryption: false,
    },
    SplashScreen: {
      launchAutoHide: false,
      backgroundColor: '#0a0a0a',
      showSpinner: false,
    },
  },
```

### Rules

- Place `CapacitorSQLite` before `SplashScreen` (alphabetical order, matching howDays convention).
- Use the exact string `'Library/CapacitorDatabase'` for `iosDatabaseLocation`. This is the standard location used by howDays, the Constellation reference, and the plugin's documentation.
- Both encryption flags are `false`. Bubls does not use SQLCipher.
- Do NOT add `LiveUpdate` or any other plugin config -- only `CapacitorSQLite`.
- Do NOT change `SplashScreen`, `appId`, `appName`, `webDir`, or `server` config.

### Files to Leave Alone

- `src/app/shared/sqlite/sqlite.service.ts` -- no changes. The service code is correct.
- `src/app/shared/sqlite/sqlite.model.ts` -- no changes.
- `src/app/features/checkin/services/checkin-data.service.ts` -- no changes. The consumer is correct.
- `src/app/shared/capacitor/capacitor-base.service.ts` -- no changes.
- `ios/App/Podfile` -- already has `CapacitorCommunitySqlite` pod. No changes.
- `package.json` -- already has `@capacitor-community/sqlite`. No changes.

## 6. Web Fallback Analysis

The `SqliteService` web fallback is intentionally minimal:

| Method | Web behavior | Acceptable? |
|--------|-------------|-------------|
| `addUpgradeStatements()` | No-op (returns immediately) | Yes -- no DB to migrate |
| `query()` | Returns `{ values: [] }` | Yes -- empty results, UI shows empty state |
| `execute()` | No-op | Yes -- writes silently dropped |
| `close()` | No-op | Yes |

`CheckinDataService.init()` on web:
1. Calls `addUpgradeStatements()` -- no-op, returns.
2. Calls `query()` warming SELECT -- returns `{ values: [] }`, no crash.
3. Sets `initialized = true`.
4. Calls `expireStale()` -- calls `execute()` which is no-op.

**Verdict**: The web fallback is safe. It does not crash, it returns empty data, and the UI should handle empty state gracefully (no sessions to show). An `sql.js` web implementation for dev mode would be nice but is out of scope for this fix. The existing behavior is consistent with how `AppSettingsService` works on web.

**No changes needed for web fallback.**

## 7. iOS Sync Steps

After modifying `capacitor.config.ts`, the iOS Xcode project must be re-synced. Capacitor compiles `capacitor.config.ts` into `ios/App/App/capacitor.config.json` during sync.

### Commands

```bash
cd /projects/bubls

# 1. Build the Angular app (required before cap sync copies www/)
ng build

# 2. Sync the iOS project -- this does three things:
#    a. Copies www/ into ios/App/App/public/
#    b. Compiles capacitor.config.ts -> ios/App/App/capacitor.config.json
#    c. Runs pod install if Podfile changed (it hasn't, so this is a no-op)
npx cap sync ios
```

Or use the existing npm script which chains both:

```bash
npm run cap:sync    # = "ng build && cap sync ios"
```

### What `cap sync` Updates

| File | What changes |
|------|-------------|
| `ios/App/App/capacitor.config.json` | Gains `CapacitorSQLite` block in `plugins` |
| `ios/App/App/public/` | Rebuilt Angular app copied in |

The `Podfile` and `Podfile.lock` should NOT change because the `CapacitorCommunitySqlite` pod is already installed.

## 9. Tests

No new tests are needed. Rationale:

- **Unit tests**: `SqliteService` and `CheckinDataService` are already tested with mocked SQLite calls. The config file is not testable at the unit level -- it is a build-time input to the Capacitor CLI, not an Angular injectable.
- **Integration tests**: The real verification is runtime on iOS (section 8c). There is no headless iOS simulator test harness in the project.
- **Existing tests**: Must all pass unchanged. The config change does not affect any TypeScript source, so no test should break.

If a future task adds end-to-end Capacitor tests, verifying `iosDatabaseLocation` would be appropriate there.
