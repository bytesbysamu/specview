## 1. Context

Task 1 declares every HTTP shape involved in SaaS monetisation into `openapi.yaml` before a single line of implementation is written. The three billing routes (`POST /api/billing/create-checkout-session`, `POST /api/billing/webhook`, `GET /api/billing/status`) and the `UsageLimitError` 429 body are the seam between the billing module (Task 2), the usage metering decorator (Task 3), and the Angular surface (Task 4). By committing the DTOs from this task, Tasks 2 and 3 get concrete Python classes to validate against from day one, preventing the drift that accumulates when contract and implementation grow in parallel. The task also adds the forward-declared `securitySchemes.bearerAuth` entry and `components/responses/Unauthorized` reference — without these, the `security:` annotations on the two auth-gated billing routes fail OpenAPI spec validation.

Three architecture pre-conditions are resolved as follows before this guide opens: **(a) Past-due access rule** — Option A is assumed (user retains Pro access until `customer.subscription.deleted`; `invoice.payment_failed` does NOT write `User.plan`). This has no effect on the OpenAPI contract shape. **(b) Sixth webhook event** — the webhook endpoint in OpenAPI accepts the raw Stripe payload without enumerating event types; the handler dispatch table is an implementation detail confined to Task 2's `service.py`. The sixth event does not change the contract. **(c) Daily free-tier cap values** — the proposed values (`bootstrap=3`, `task_gen=20`, `spec_gen=10`) are documented as examples in the `UsageLimitError` schema; they live in `modules/usage/service.py` (Task 3), not in the OpenAPI contract.

**Trade-offs considered:**
- **Adding security annotations now (forward declaration) vs. deferring until Task 2 implements `require_auth`** — add now; `openapi_spec_validator` (called by `spec_validOpenApi30` in the test suite) raises on `security:` annotations that reference an undeclared scheme. The forward declaration is a zero-cost contract commitment with no runtime effect.
- **Inline `BillingStatusResponse.status` enum vs. extracting a shared `SubscriptionStatus` component schema** — inline; ELA Pattern #5 prohibits shared abstractions before a second consumer exists. One route, one inline enum.
- **One commit for YAML + DTOs vs. two separate commits** — single commit; `allOpenApiSchemas_haveGeneratedModels` in `test_dtos.py` and `make check-dtos` in CI both fail if YAML and DTOs are committed separately. They are always a paired unit.

```yaml
  /api/billing/create-checkout-session:
    post:
      summary: Create a Stripe Checkout session for the Pro plan
      operationId: createCheckoutSession
      tags: [billing]
      security:
        - bearerAuth: []
      responses:
        '200':
          description: >
            Stripe-hosted checkout URL. The Angular client performs a full
            browser redirect to this URL — no in-page payment form.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/CheckoutSessionResponse'
        '401':
          $ref: '#/components/responses/Unauthorized'

  /api/billing/webhook:
    post:
      summary: >
        Receive Stripe webhook events. Signature verified via Stripe-Signature
        header against STRIPE_WEBHOOK_SECRET. No bearer auth — Stripe is the caller.
      operationId: stripeWebhook
      tags: [billing]
      security: []
      parameters:
        - name: Stripe-Signature
          in: header
          required: true
          schema:
            type: string
          description: >
            HMAC signature set by Stripe on every webhook delivery.
            Verified by service.py before any handler runs; unsigned payloads
            return 400.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              description: >
                Raw Stripe event payload. Structure is Stripe-defined;
                spec-doc does not validate inner fields beyond signature
                verification.
      responses:
        '200':
          description: Event received and dispatched.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/WebhookAckResponse'
        '400':
          description: Stripe signature verification failed.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ErrorResponse'

  /api/billing/status:
    get:
      summary: >
        Return the authenticated user's current subscription plan, status,
        period end, and a live Customer Portal URL for self-service management.
      operationId: getBillingStatus
      tags: [billing]
      security:
        - bearerAuth: []
      responses:
        '200':
          description: Subscription snapshot for the authenticated user.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BillingStatusResponse'
        '401':
          $ref: '#/components/responses/Unauthorized'
```

**Action**: Three edits to the `components:` block.

**2a — billing schemas** — append after `RepairProjectResponse` (the last existing schema, closing at approximately line 1157) and before `responses:`:

**File**: `api/openapi.yaml`

```yaml
    UsageLimitError:
      type: object
      required:
        - error
        - feature
        - limit
        - reset_at
        - upgrade_url
      properties:
        error:
          type: string
          description: Human-readable description of the limit that was hit.
          example: Daily limit reached for task_gen
        feature:
          type: string
          enum: [bootstrap, task_gen, spec_gen]
          description: >
            Feature key that hit the daily cap. Matches keys in
            DAILY_FREE_TIER_LIMITS in modules/usage/service.py.
          example: task_gen
        limit:
          type: integer
          minimum: 0
          description: Daily cap for this feature on the free tier.
          example: 20
        reset_at:
          type: string
          format: date-time
          description: UTC midnight at which the daily counter resets.
          example: "2026-04-27T00:00:00Z"
        upgrade_url:
          type: string
          description: >
            App-relative path to the upgrade page. Angular's 429 interceptor
            navigates to this URL when a UsageLimitError is received.
          example: /upgrade

    CheckoutSessionResponse:
      type: object
      required:
        - url
      properties:
        url:
          type: string
          description: >
            Stripe-hosted checkout URL. Redirect the browser to this value.
            Valid for a single checkout attempt; do not cache.
          example: https://checkout.stripe.com/pay/cs_test_xxx

    WebhookAckResponse:
      type: object
      required:
        - received
      properties:
        received:
          type: boolean
          description: >
            Always true on a 200 response. Signals Stripe that the payload
            was accepted; Stripe will not retry.
          example: true

    BillingStatusResponse:
      type: object
      required:
        - plan
      properties:
        plan:
          type: string
          enum: [free, pro]
          description: >
            Current plan. Written exclusively by Stripe webhook handlers;
            no in-app code path may set this to 'pro'.
          example: free
        status:
          type: string
          nullable: true
          enum: [active, past_due, canceled]
          description: >
            Stripe subscription status. Null for free users who have never
            subscribed.
          example: active
        current_period_end:
          type: string
          format: date-time
          nullable: true
          description: >
            End of the current billing period. Null for free users.
          example: "2026-05-26T00:00:00Z"
        manage_url:
          type: string
          nullable: true
          description: >
            Live Stripe Customer Portal URL. Generated per-request (Stripe
            session tokens expire). Null until the user completes their first
            checkout session; the customer ID is created lazily.
          example: https://billing.stripe.com/p/session/xxx
```

    """UsageLimitError accepts all required fields and round-trips through model_dump."""
