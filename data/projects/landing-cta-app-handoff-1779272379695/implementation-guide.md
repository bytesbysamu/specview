# Implementation Guide: Landing CTA App Handoff

## Overview

This epic converts the landing page's Analyze CTA from a self-contained demo into a real onboarding funnel. Task 1 upgrades the public analyze backend to create a genuine filesystem project and persist results to disk. Task 2 rewrites the Angular `/analyze` route's component to read a `job` query parameter instead of a base64 URL hash, poll the public status endpoint, and render the analysis without auth. Task 3 strips `analyze.js` of all result-rendering logic and replaces it with a POST-then-redirect flow. Task 4 adds a TTL cleanup daemon that sweeps anonymous projects older than 48 hours. Task 1 must land first; Tasks 2 and 4 can proceed in parallel after it; Task 3 ships last once both backend and app are live.

## Shared Pre-flight

- `PROJECTS_DIR` env var must be set and writable — anonymous projects land in the same directory as authenticated ones.
- `CHAIN_PROVIDER=cli` always — never SDK provider in Docker. No change needed; this is the running configuration.
- All OpenAPI contract changes go into `api/openapi.yaml` before implementation. Run `npm run generate:api` in `web-ng/` after any schema change. Do not edit generated files in `web-ng/src/app/api/` by hand.
- The Task 1 Alembic migration (`api/migrations/versions/0003_anonymous_project.py`) must be applied before the app starts. In Docker: `docker compose build api && docker compose up -d api` runs migrations automatically.
- `app.specview.dev` is the Angular app origin. Confirm or define `APP_ORIGIN` in `landing/analyze.js` as a constant at the top of the IIFE.
- Run `pytest api/` after each backend task before moving forward.

## Task 1: Backend: Anonymous Project Creation & Job Polling  [Effort: 2 days]

### What

Upgrade `POST /api/public/analyze` to create a real filesystem project before spawning the analysis thread, persist the braindump and analysis output to disk, and update the status endpoint to include the project ID and fall back to reading completed results from the filesystem when the job has been evicted from the in-memory store. The job ID and project ID are the same value — no mapping table needed.

### Files

- **Modify**: `api/modules/data/projects/models.py` — make `user_id` nullable (`Optional[int]`), add `anonymous: bool = Field(default=False)` column
- **Create**: `api/migrations/versions/0003_anonymous_project.py` — Alembic migration making `project.user_id` nullable and adding the `anonymous` boolean column
- **Modify**: `api/modules/ai/services/public_analyze.py` — use the project slug as the job ID; create project directory and write `braindump.md` and `project.json` before spawning the thread; write `analysis.md` on completion; add disk-fallback path in `get_job`
- **Modify**: `api/modules/data/projects/repository.py` — add `create_anonymous(name, slug) -> Project` to `SqlProjectRepository`
- **Modify**: `api/modules/ai/routes/public_analyze.py` — include `project_id` and `braindump` in the status response JSON
- **Modify**: `api/openapi.yaml` — update `POST /api/public/analyze` 202 response to include `project_id`; update `GET /api/public/analyze/{job_id}` response to include `project_id`, `braindump`

### Steps

1. Open `api/modules/data/projects/models.py`. Change `user_id: int` to `user_id: Optional[int]` and add `anonymous: bool = Field(default=False)`. Add `Optional` to the `typing` import if not already present.

2. Scaffold the migration from `api/`: `alembic revision --autogenerate -m "anonymous_project"`. Rename the generated file to `api/migrations/versions/0003_anonymous_project.py`. Verify it alters the `project` table — `user_id` becomes nullable and `anonymous` boolean is added with `server_default='0'`.

3. Add `create_anonymous(self, name: str, slug: str) -> Project` to `SqlProjectRepository` in `api/modules/data/projects/repository.py`. Insert a `Project` row with `user_id=None`, `anonymous=True`, `name=name`, `slug=slug`, `git_repo_path=slug`. Commit inside the method per the service-layer convention.

4. Open `api/modules/ai/services/public_analyze.py`. In `start_analysis`, replace `job_id = str(uuid.uuid4())` with a slug generated by the same `_make_id` formula used in `modules.data.projects.service` (import it from there). Derive the name from the first 40 characters of the braindump. The slug serves as both `project_id` and `job_id`.

5. After generating the slug, create the project directory at `Path(PROJECTS_DIR) / project_id`. Write `braindump.md` (the raw braindump text) and `project.json` (matching the shape written by `create_project` in `modules.data.projects.service`: `{"name": ..., "createdAt": ..., "anonymous": true}`). Import `PROJECTS_DIR` from `config`. Then call `SqlProjectRepository().create_anonymous(name=derived_name, slug=project_id)` — log and continue if this DB write fails.

6. Update `_complete_job` to also write `analysis.md` to `Path(PROJECTS_DIR) / project_id` with the completed analysis text. This write must happen before the `running` flag is cleared so a concurrent poll reads consistent state.

7. Add a disk-fallback path in `get_job`: if `job_id` is absent from `_JOBS`, check whether `Path(PROJECTS_DIR) / job_id / analysis.md` exists. If it does, return a synthetic dict `{"running": False, "done": True, "analysis": <file content>, "project_id": job_id, "braindump": <braindump.md content if present>, "error": None}`.

8. Update `get_analysis_status` in `api/modules/ai/routes/public_analyze.py` to include `project_id` and `braindump` from the job dict in the response JSON. Both may be `None` for in-flight jobs — the client handles nulls.

9. Update `api/openapi.yaml`: add `project_id` (string, nullable) and `braindump` (string, nullable) to the `GET /api/public/analyze/{job_id}` response schema; add `project_id` to the `POST /api/public/analyze` 202 body. Run `npm run generate:api` in `web-ng/`.

### Verify

- `curl -X POST http://localhost:8095/api/public/analyze -H 'Content-Type: application/json' -d '{"braindump":"test idea for my project"}' -i` returns 202 with `job_id` and `project_id` (same value). `ls data/projects/<job_id>/` shows `braindump.md` and `project.json`.
- After polling until `done=true`, `data/projects/<job_id>/analysis.md` exists. The response JSON includes `project_id` and `braindump` fields.
- Restart the API container after a completed job; `GET /api/public/analyze/<job_id>` still returns the analysis (disk fallback, not memory).
- `pytest api/` passes, including `test_structural.py` and `test_app_routes_are_documented`.

## Task 2: App: Anonymous Analyze Route with Auth Bypass  [Effort: 2 days]

### What

Rewrite `AnalyzeResultComponent` to read a `job` query parameter, poll `GET /api/public/analyze/<job_id>` via a new `ProjectsService` method, and render the analysis in the existing layout. The `/analyze` route in `app.routes.ts` already has no `canActivate` guard — no routing changes are needed. The current component uses `LandingHandoffService` and the full three-step bootstrap pipeline; the new implementation replaces that with direct polling of the lightweight public endpoint.

### Files

- **Modify**: `web-ng/src/app/analyze-result/analyze-result.component.ts` — inject `ActivatedRoute` and `ProjectsService`; remove `LandingHandoffService` dependency; read `job` query param; poll `pollPublicAnalysis`; render analysis markdown and braindump; clear interval on destroy
- **Modify**: `web-ng/src/app/services/projects.service.ts` — add `pollPublicAnalysis(jobId: string): Promise<PublicAnalysisStatus>` method and `PublicAnalysisStatus` interface
- **Modify**: `api/openapi.yaml` — ensure `GET /api/public/analyze/{job_id}` is fully documented (carried over from Task 1)
- **Run**: `npm run generate:api` in `web-ng/` after any OpenAPI change

### Steps

1. Confirm `api/openapi.yaml` has a complete schema for `GET /api/public/analyze/{job_id}`. Run `npm run generate:api` in `web-ng/`.

2. Open `web-ng/src/app/services/projects.service.ts`. Define `PublicAnalysisStatus` interface: `{ running: boolean; done: boolean; analysis: string | null; braindump: string | null; project_id: string | null; error: string | null }`. Add `pollPublicAnalysis(jobId: string): Promise<PublicAnalysisStatus>` using `firstValueFrom(this.http.get<PublicAnalysisStatus>('/api/public/analyze/' + jobId))`. No Authorization header.

3. Open `web-ng/src/app/analyze-result/analyze-result.component.ts`. Remove the `LandingHandoffService` injection and all references to `handoffSvc`, `startAnonymousBootstrap`, `pollAnonymousBootstrap`, `BootstrapFile`, and `BootstrapJobStatus`. Inject `ActivatedRoute` (from `@angular/router`) and `ProjectsService`.

4. Redefine the component signals: keep `isRunning` and `fatalError`; add `analysisText = signal<string | null>(null)` and `braindumpContent = signal<string | null>(null)`. Replace the multi-file tab signals (`files`, `activeFilename`) with these — there is one output document from the public endpoint. Derive `parsedContent` from `analysisText` using `marked.parse` + `DOMPurify.sanitize` as already done.

5. In `ngOnInit`, read `jobId = this.route.snapshot.queryParamMap.get('job')`. If absent, `fatalError.set('No job ID provided. Return to the landing page and try again.')` and return. Otherwise call `_startPolling(jobId)` and `isRunning.set(true)`.

6. Implement `_startPolling(jobId: string)` with `setInterval` at 2500ms. On each tick, call `this.projectsSvc.pollPublicAnalysis(jobId)`. On success with `status.done=true`: stop polling, `isRunning.set(false)`, `analysisText.set(status.analysis)`, `braindumpContent.set(status.braindump)`, and set `fatalError` if `status.error` is truthy. On a caught 404, stop polling and `fatalError.set('Analysis job not found. It may have expired.')`. Store the handle as `private pollInterval: ReturnType<typeof setInterval> | null = null`. Call `clearInterval` in `ngOnDestroy`.

7. Update the template. Spinner while `isRunning()`. When `analysisText()` is non-null, render `[innerHTML]="parsedContent()"` in `div.markdown-body`. Show the braindump in a collapsible `<details>` element above the analysis labeled "Your braindump". Keep the `data-test="analyze-conversion-gate"` block with the "Save your spec" sign-up CTA — show it when `!isRunning() && !fatalError()`.

8. Verify `web-ng/src/app/app.routes.ts` has no `canActivate` on the `analyze` path — it does not. No routing changes needed.

### Verify

- Navigate to `http://localhost:4200/analyze?job=<valid-job-id>` — analysis renders, no login prompt.
- Navigate to `http://localhost:4200/analyze` — error message visible immediately, no spinner loop.
- Navigate to `http://localhost:4200/analyze?job=doesnotexist` — 404 stops polling and surfaces "Analysis job not found".
- Conversion gate CTA is visible after analysis completes.
- `ng build` produces no TypeScript errors.

## Task 3: Landing Page: POST + Redirect Handoff  [Effort: 0.5 days]

### What

Replace the inline result-rendering logic in `landing/analyze.js` with a POST-then-redirect flow. Once the 202 response arrives with a `job_id`, redirect the browser to the Angular app. All polling, markdown rendering, DOM result manipulation, and conversion CTA logic is removed — the landing page's only job after the POST response is to navigate away.

### Files

- **Modify**: `landing/analyze.js` — remove `pollAnalysis`, `showResult`, `hideResult`, `showConversionCta`, `hideConversionCta`, `getResultEl`, `getConversionCta`, `startTimer`, `stopTimer`, `getTimerEl`, `timerHandle`, `elapsedSeconds`, `POLL_INTERVAL_MS`; add `APP_ORIGIN` constant; replace the post-success handler with `window.location.href` redirect
- **Modify**: `landing/index.html` — remove the `#analyze-result` and `#conversion-cta` DOM elements and any associated markup

### Steps

1. Add `var APP_ORIGIN = 'https://app.specview.dev';` at the top of the IIFE in `landing/analyze.js`, before any function definitions.

2. Delete the following from `landing/analyze.js` entirely: `pollAnalysis`, `stopPolling`, `startTimer`, `stopTimer`, `showResult`, `hideResult`, `showConversionCta`, `hideConversionCta`, `getResultEl`, `getConversionCta`. Delete the `pollHandle`, `timerHandle`, `elapsedSeconds`, and `POLL_INTERVAL_MS` variable declarations.

3. In `window.submitAnalysis`, replace the `pollAnalysis(data.job_id)` call with `window.location.href = APP_ORIGIN + '/analyze?job=' + encodeURIComponent(data.job_id);`. The `disableForm()` and `showLoading()` calls before the fetch stay in place.

4. Keep all error-handling paths unchanged: 429 rate-limit messaging, validation for empty or over-length braindump, and the generic server error catch. In error paths, `hideLoading()` and `enableForm()` are still needed.

5. Open `landing/index.html`. Remove the `#analyze-result` element and its contents. Remove the `#conversion-cta` element and its contents. Remove the `#analyze-timer` element if present. Check landing CSS files for selectors targeting these removed IDs and delete those rules.

6. For local testing, temporarily override `APP_ORIGIN` to `http://localhost:4200` — do not commit the override.

### Verify

- Submit a valid braindump on the landing page — browser navigates to `app.specview.dev/analyze?job=<id>` within the POST round-trip.
- Submit an empty textarea — error message on landing page, no redirect.
- Hit the rate limit — 429 error on landing page, no redirect.
- View source of the landing page — `#analyze-result` element is absent.

## Task 4: Anonymous Project TTL Cleanup  [Effort: 1 day]

### What

Add a daemon timer thread started during app initialization that queries the database for anonymous projects older than a configurable TTL (default 48 hours), deletes their filesystem directories, and removes their database rows. No external scheduler — the thread lives inside the Flask/gunicorn process, matching the existing daemon thread pattern.

### Files

- **Create**: `api/modules/ai/services/anonymous_cleanup.py` — cleanup logic and `start_cleanup_thread(ttl_hours, interval_hours)` entry point
- **Modify**: `api/modules/data/projects/repository.py` — add `list_anonymous_older_than(cutoff: datetime) -> list[Project]` and `delete_by_id(project_id: int) -> None` to `SqlProjectRepository`
- **Modify**: `api/create_app.py` — call `start_cleanup_thread()` after blueprints are registered, guarded by `not app.config.get("TESTING")`

### Steps

1. Open `api/modules/data/projects/repository.py`. Add `list_anonymous_older_than(self, cutoff: datetime) -> list[Project]`: query `select(Project).where(Project.anonymous == True, Project.created_at < cutoff)`. Add `delete_by_id(self, project_id: int) -> None`: fetch by ID, `session.delete(project)`, commit.

2. Create `api/modules/ai/services/anonymous_cleanup.py`. Write `_delete_project_dir(slug: str) -> None`: resolve `Path(PROJECTS_DIR) / slug`, apply the same traversal guard as `_safe_path` in `modules.data.projects.service`, call `shutil.rmtree` if the directory exists, log at DEBUG if already absent.

3. Write `_run_cleanup(ttl_hours: int) -> None`: compute `cutoff = datetime.now(timezone.utc) - timedelta(hours=ttl_hours)`, call `SqlProjectRepository().list_anonymous_older_than(cutoff)`, loop over results calling `_delete_project_dir(project.slug)` then `repo.delete_by_id(project.id)`. Wrap per-project operations in `try/except` so one bad project does not abort the sweep. Log an INFO summary with count deleted and count errors.

4. Write `start_cleanup_thread(ttl_hours: int = 48, interval_hours: int = 6) -> None`. Use a `threading.Thread` with a `while True` loop that sleeps `interval_hours * 3600` seconds at the top of each iteration (sleep-first so the first cleanup runs after one full interval). Set `daemon=True` before starting the thread.

5. Open `api/create_app.py`. After the `_build_slug_index()` block and before `return app`, read `ANON_PROJECT_TTL_HOURS` from `os.environ` (default `"48"`), parse to int, and call `start_cleanup_thread(ttl_hours=ttl_hours, interval_hours=6)`. Wrap in `if not app.config.get("TESTING"):`.

6. Add `ANON_PROJECT_TTL_HOURS=48` to `.env.example` (or the Docker Compose env block) as documentation of the tunable.

### Verify

- `pytest api/` passes — cleanup thread is not started in test mode.
- Insert a test anonymous project row with `created_at` 50 hours in the past and create its directory. Call `_run_cleanup(ttl_hours=48)` directly — confirm the directory is gone and the DB row is deleted.
- A project with `anonymous=False` sharing the same old `created_at` is untouched.
- `docker compose logs -f api` shows an INFO cleanup summary approximately 6 hours after first deploy, no exception traceback.
