# 🏗️ Port howDays Boilerplate – Solution Architecture

**Purpose**: Technical design for migrating Bubls to CocoaPods and porting howDays' infrastructure modules.

**Epic Reference**: See [Epic](./epic.md) for scope and business context.

---

## Architecture Overview

This capability operates entirely on the iOS client side. No backend changes, no Neon schema changes, no API endpoints. The work has two layers: (1) a build-system migration from SPM to CocoaPods that changes how native dependencies resolve, and (2) four shared modules (`shared/sqlite/`, `shared/subscriptions/`, `shared/live-update/`, plus Capacitor plugin config) that port proven patterns from howDays.

Every module follows the adapter pattern from the architecture principles: a service interface that feature code imports, backed by either the real Capacitor plugin or a mock implementation gated by environment flag. Feature code never imports Capacitor plugins directly — it goes through the shared adapter. This is enforced by structural tests.

The modules have one internal dependency: `shared/subscriptions/` uses `shared/sqlite/` to cache entitlement state locally. All other modules are independent. The build-system migration (task 1) is the universal prerequisite — nothing else can proceed until CocoaPods resolves and the app builds.

---

## Design Principles

| Principle | Application |
|-----------|-------------|
| Adapter (every feature service) | Each shared module wraps a Capacitor plugin behind an adapter interface. Mock mode via `environment.mock` flag. Feature code imports the adapter, never the plugin directly. |
| Feature = Bounded Context | Each module is a self-contained directory in `shared/` with its own model, service, mock, and tests. No cross-module imports except `subscriptions → sqlite` (explicit dependency). |
| Not-yet-built is the right state | SQLite creates only `app_settings` — no speculative tables. RevenueCat reads offerings from dashboard config — no hardcoded product IDs. Live-update uses placeholder bundle URL — configured when there's a real bundle to serve. |
| Ship the car, not the engine | CocoaPods migration is the car. It unblocks three broken plugins immediately. The shared modules are passengers — useful, but the migration alone delivers the critical fix. |
| Structural tests — add as encountered | Add tests that grep for direct Capacitor plugin imports outside `shared/` adapters. One test per boundary violation class. |

## Component Design

### Task 1: SPM → CocoaPods Migration

**Purpose**: Replace the iOS dependency management system so `cap sync` auto-resolves all Capacitor plugins via CocoaPods.

**Components**:
- `ios/App/Podfile` — Auto-generated by `cap sync`, then committed. Lists all Capacitor plugins as pod dependencies.
- `ios/App/Podfile.lock` — Committed for reproducible builds. Pins exact versions.
- `ios/App/App.xcworkspace` — Generated by `pod install`. This replaces `App.xcodeproj` as the entry point for Xcode.
- `capacitor.config.ts` — No changes needed for this task; Capacitor already knows the plugin list from `package.json`.

**Files to remove**:
- `ios/App/Package.swift` — SPM package definition
- `ios/App/Package.resolved` — SPM lock file
- Any SPM-specific entries in `ios/App/App.xcodeproj/project.pbxproj` (Capacitor regenerates the project file on `cap sync`)

**Patterns**: One-time migration. No adapter needed — this is build tooling, not runtime code.

**Verification**: `cd ios/App && pod install && xcodebuild -workspace App.xcworkspace -scheme App -sdk iphonesimulator build`

### Task 2: Capacitor Plugin Verification

**Purpose**: Confirm every installed plugin resolves at the native level and functions on a real device.

**Components**:
- No new files. This task is a verification pass.
- Optionally, a `shared/plugin-check/` utility that calls each plugin's echo/status method on app launch and logs results — useful during development, removable later.

**Plugin matrix**:

| Plugin | npm Package | Expected CocoaPods Pod | Test Action |
|--------|------------|----------------------|-------------|
| Speech Recognition | `@capacitor-community/speech-recognition` | `CapacitorCommunitySpeechRecognition` | Request permission → record → get transcript |
| Media | `@capacitor-community/media` | `CapacitorCommunityMedia` | Save a canvas-rendered image to photo library |
| Camera | `@capacitor/camera` | `CapacitorCamera` | Capture photo → display in `<img>` |
| RevenueCat | `@revenuecat/purchases-capacitor` | `PurchasesHybridCommon` | Initialize SDK → fetch offerings (no purchase) |

**Patterns**: Manual acceptance testing, not automated. Real device required for camera, media, and speech-recognition (simulator stubs these).

### Task 3: SQLite Local Storage Module

**Purpose**: Provide a local key-value and relational storage layer backed by SQLite, with a forward migration system.

**Components**:
- `src/app/shared/sqlite/sqlite.adapter.ts` — Public interface: `get(key)`, `set(key, value)`, `delete(key)`, `query(sql, params)`, `runMigrations()`. Injected via `inject(SqliteAdapter)`.
- `src/app/shared/sqlite/sqlite.service.ts` — Real implementation using `@capacitor-community/sqlite`. Opens database, executes queries, runs migrations in order.
- `src/app/shared/sqlite/sqlite.mock.ts` — In-memory Map-based implementation for tests and browser dev. Toggled via `environment.mock`.
- `src/app/shared/sqlite/sqlite.model.ts` — Types: `Migration { version: number; name: string; sql: string }`, `AppSetting { key: string; value: string; updatedAt: string }`.
- `src/app/shared/sqlite/migrations/001_app_settings.sql` — `CREATE TABLE IF NOT EXISTS app_settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT NOT NULL DEFAULT (datetime('now')))`.
- `src/app/shared/sqlite/sqlite.adapter.spec.ts` — Tests against mock implementation: set/get round-trip, delete removes key, migration creates table.

**Patterns**:
- Adapter pattern: `SqliteAdapter` is a class with the public interface. `SqliteService` extends it (real), `SqliteMock` extends it (test). Provider in `app.config.ts` switches based on environment.
- Migration runner: on `runMigrations()`, reads a `schema_version` table (auto-created), compares against migration file list, runs missing migrations in order. Same pattern as Alembic but client-side.

**Data flow**:
```
Feature code → SqliteAdapter.get('theme') → SQLite DB (device) or Map (browser)
App launch → SqliteAdapter.runMigrations() → executes 001_app_settings.sql if schema_version < 1
```

### Task 4: RevenueCat Subscription Module

**Purpose**: Provide subscription management and a paywall modal, configured entirely from RevenueCat's dashboard.

**Components**:
- `src/app/shared/subscriptions/subscription.adapter.ts` — Public interface: `initialize(apiKey)`, `getOfferings()`, `purchase(pkg)`, `restorePurchases()`, `getActiveEntitlements()`, `isEntitled(entitlementId)`.
- `src/app/shared/subscriptions/subscription.service.ts` — Real implementation using `@revenuecat/purchases-capacitor`. Caches entitlements in SQLite via `SqliteAdapter.set('rc_entitlements', JSON.stringify(entitlements))`.
- `src/app/shared/subscriptions/subscription.mock.ts` — Returns configurable mock offerings and entitlements. Defaults to free tier.
- `src/app/shared/subscriptions/subscription.model.ts` — Types: `Offering`, `Package`, `Entitlement`, `SubscriptionStatus`.
- `src/app/shared/subscriptions/paywall-modal/paywall-modal.component.ts` — Standalone Ionic modal. Fetches offerings from `SubscriptionAdapter`, displays packages with price/description, handles purchase flow, dismisses on success or cancel.
- `src/app/shared/subscriptions/paywall-modal/paywall-modal.component.spec.ts` — Tests with mock adapter: shows offerings, purchase triggers adapter, error shows retry.
- `src/app/shared/subscriptions/subscription.adapter.spec.ts` — Tests: initialize sets API key, getOfferings returns mock data, isEntitled checks cached state.

**Patterns**:
- Adapter pattern: same as SQLite. Real RevenueCat SDK vs mock, environment-gated.
- Feature Guard with Null Object: `isEntitled(id)` returns false when SDK is not initialized or network fails — features degrade to free tier, never crash.
- Observer: `SubscriptionAdapter` exposes a `status$` signal that features can read. Paywall modal writes to it on purchase success.

**Initialization flow**:
```
app.config.ts → APP_INITIALIZER → SubscriptionAdapter.initialize(RC_API_KEY)
                                 → SqliteAdapter.get('rc_entitlements') → hydrate cache
                                 → Purchases.getCustomerInfo() → refresh if online
```

### Task 5: Live-Update Module

**Purpose**: Enable OTA JavaScript bundle updates without App Store review.

**Components**:
- `src/app/shared/live-update/live-update.adapter.ts` — Public interface: `checkForUpdate()`, `downloadUpdate()`, `applyUpdate()`, `getCurrentVersion()`.
- `src/app/shared/live-update/live-update.service.ts` — Real implementation using `@capawesome/capacitor-live-update`. Checks bundle server on app launch, downloads if new version available, applies on next app restart.
- `src/app/shared/live-update/live-update.mock.ts` — No-op implementation for dev/test. `checkForUpdate()` always returns `{ available: false }`.
- `src/app/shared/live-update/live-update.model.ts` — Types: `UpdateInfo { available: boolean; version?: string; size?: number }`.
- `capacitor.config.ts` — Add `LiveUpdate` plugin config with placeholder `appId` and `bundleUrl`.

**Patterns**:
- Adapter pattern: same as above.
- Silent update: check on launch, download in background, apply on next cold start. No UI interruption.

### Task 6: CI/CD Pipeline Update

**Purpose**: Update build pipeline to use CocoaPods workspace.

**Components**:
- `.github/workflows/build-ios.yml` — Add `pod install` step before `xcodebuild`. Change `-project` to `-workspace`. Add CocoaPods cache step (`actions/cache` with `Podfile.lock` hash key).
- `fastlane/Fastfile` (or `Gymfile`) — Update `workspace` parameter from `App.xcodeproj` to `App.xcworkspace`.
- `.gitignore` — Add `ios/App/Pods/` (vendors not committed; `Podfile.lock` is committed).

## Execution Flow

```
[Phase 1 — Foundation]
   Task 1: SPM → CocoaPods ──→ Task 2: Plugin Verification
                                Task 6: CI/CD Update
                                   │
[Phase 2 — Modules, parallel]      ▼
   Task 3: SQLite ──────────┐
   Task 4: RevenueCat ──────┤ (4 depends on 3 for entitlement cache)
   Task 5: Live-Update ─────┘
```

Phase 1 is serial: migration must complete and be verified before modules can build on it. Task 6 can run in parallel with task 2 since it's CI config, not runtime code.

Phase 2 tasks are mostly parallel. Task 4 has a soft dependency on task 3 (uses SQLite for entitlement caching), but the adapter interface can be defined first and wired later. Tasks 3 and 5 are fully independent.

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| SPM removal | Fully remove, no fallback | Maintaining two dependency systems is worse than migrating once. CocoaPods is the Capacitor ecosystem standard. howDays proves it works. |
| CocoaPods vendor policy | Don't commit `Pods/` directory | Commit `Podfile.lock` for reproducibility. `Pods/` is regenerated by `pod install` in CI. Keeps repo size small. |
| SQLite initial table | `app_settings` key-value only | Validates the migration layer end-to-end without speculating on future schema. One table is enough to prove the pattern. Additional tables are feature-level concerns. |
| Entitlement caching | SQLite, not UserDefaults | Consistent with the storage architecture (one storage layer, not two). SQLite is already available. UserDefaults can't be queried or migrated as cleanly. |
| Live-update scope | Client capability only, no server | The plugin needs a bundle URL configured, but standing up a CDN is operational work that happens when there's a real bundle to serve. Porting the client-side code now means the capability is ready when needed. |
| Paywall modal design | Business-agnostic, reads from RevenueCat dashboard | Product names, prices, and descriptions come from RevenueCat's offering configuration, not from hardcoded strings. Same modal works for Bubls, howDays, or any future app. |
| Module location | `src/app/shared/` subdirectories | Architecture principles mandate shared code in `shared/`. Each module is a bounded context within shared, with its own adapter, mock, model, and tests. |
| Adapter vs direct plugin import | Adapter always | Architecture principles: "No direct imports from `{pkg}.providers.*` in feature code." Capacitor plugins are providers. Structural tests enforce the boundary. |
