# Task 1: SPM → CocoaPods Migration

**Purpose**: Replace Swift Package Manager with CocoaPods as the iOS dependency manager for Bubls, unblocking all Capacitor community plugins that fail to resolve under SPM's Proxy-based package resolution.

**Effort**: 1 day

**Dependencies**: None — this is the universal prerequisite for all other tasks in the epic.

**Parallel With**: —

**Blocks**: Task 2 (Plugin Verification), Task 3 (SQLite Module), Task 4 (RevenueCat Module), Task 5 (Live-Update Module), Task 6 (CI/CD Pipeline Update)

**Related**:
- [Solution Architecture](./architecture.md)
- [Epic](./epic.md)

## 1. Context

Bubls uses Capacitor 7 to bridge the Angular 19 + Ionic 8 frontend to native iOS. The project was scaffolded from the Constellation repo, which ships with Swift Package Manager for native dependency resolution. SPM works for first-party `@capacitor/*` plugins but fails for community plugins (`@capacitor-community/speech-recognition`, `@capacitor-community/media`, `@revenuecat/purchases-capacitor`, `@capawesome/capacitor-live-update`) — these plugins publish CocoaPods podspecs but not SPM-compatible `Package.swift` manifests. The howDays reference project at `{WORKSPACE}/../howDays/angular-sqlite-starter/` proves the CocoaPods path works end-to-end with these same plugins. This task removes SPM artifacts, runs `cap sync` to auto-generate a Podfile from the installed npm plugins, runs `pod install` to resolve native dependencies, and verifies the app builds and launches. No runtime code changes — this is purely build tooling.

**Trade-offs considered**:
- **Keep SPM and manually add podspecs for missing plugins** — rejected because maintaining two dependency systems creates version conflicts and `cap sync` only generates one. Every future plugin install would require manual podspec wiring.
- **Migrate to Tuist or Swift Package Collections** — rejected because the Capacitor ecosystem standardizes on CocoaPods. Swimming against ecosystem convention creates friction on every `npx cap sync`.
- **CocoaPods with committed `Pods/` directory** — rejected because `Pods/` can be 200MB+ and is fully reproducible from `Podfile.lock`. Commit `Podfile` + `Podfile.lock`, regenerate `Pods/` via `pod install` in CI.

## 3. Files

### To Create (generated by tooling, then committed)
- `ios/App/Podfile` — auto-generated by `npx cap sync ios`; lists all Capacitor plugins as pod dependencies
- `ios/App/Podfile.lock` — generated by `pod install`; pins exact dependency versions for reproducible builds
- `ios/App/App.xcworkspace/` — generated by `pod install`; replaces `.xcodeproj` as the Xcode entry point

### To Modify
- `ios/App/App.xcodeproj/project.pbxproj` — `npx cap sync ios` regenerates this; SPM references (`XCRemoteSwiftPackageReference`, `XCSwiftPackageProductDependency`, `packageReferences`) are removed automatically by Capacitor during sync
- `.gitignore` — add `ios/App/Pods/` entry to exclude vendored CocoaPods dependencies

### To Remove
- `ios/App/Package.swift` — SPM package definition (no longer needed)
- `ios/App/Package.resolved` — SPM lock file (replaced by `Podfile.lock`)

### To Leave Alone
- `capacitor.config.ts` — no changes needed; Capacitor reads the plugin list from `package.json`, not from SPM or CocoaPods config
- `package.json` — the npm-level plugin declarations drive `cap sync`; they don't change
- `src/` — no Angular/TypeScript changes; this is a native build-system migration only
- `ios/App/App/` — app source files (AppDelegate.swift, Info.plist, etc.) are not affected by the dependency manager swap

## 4. Implementation Steps

### Step 1: Remove SPM artifacts

**Action**: Delete the SPM package definition and lock file. These are replaced by CocoaPods equivalents.

**File**: `ios/App/Package.swift` (remove), `ios/App/Package.resolved` (remove)

**Pattern**:
```bash
rm ios/App/Package.swift
rm ios/App/Package.resolved
```

**Verify**: `ls ios/App/Package.swift ios/App/Package.resolved 2>&1` — expect "No such file or directory" for both.

### Step 2: Clean SPM references from Xcode project

**Action**: Open `ios/App/App.xcodeproj/project.pbxproj` and remove any `XCRemoteSwiftPackageReference`, `XCSwiftPackageProductDependency`, and `packageReferences` sections. Alternatively, let `npx cap sync ios` in Step 3 handle this — Capacitor's sync regenerates the pbxproj. If SPM entries persist after sync, remove them manually.

**File**: `ios/App/App.xcodeproj/project.pbxproj`

**Pattern** (manual removal, only if entries persist after Step 3):
```
// Remove any blocks matching these patterns:
//   XCRemoteSwiftPackageReference "..." = { ... };
//   XCSwiftPackageProductDependency "..." = { ... };
//   packageReferences = ( ... );
```

**Verify**: `grep -c "XCRemoteSwiftPackageReference\|XCSwiftPackageProductDependency\|packageReferences" ios/App/App.xcodeproj/project.pbxproj` — expect `0`.

### Step 3: Install CocoaPods (if not present)

**Action**: Ensure the `pod` command is available. CocoaPods can be installed via Homebrew (preferred on macOS) or RubyGems.

**File**: n/a (system tool installation)

**Pattern**:
```bash
# Check if pod is installed
which pod || brew install cocoapods

# Verify version
pod --version   # Expect 1.15+ (Capacitor 7 compatible)
```

**Verify**: `pod --version` — expect a version number (e.g., `1.15.2`).

### Step 4: Run Capacitor sync to generate Podfile

**Action**: Run `npx cap sync ios` from the project root. This does three things: (1) copies the web build to `ios/App/App/public/`, (2) generates `ios/App/Podfile` listing all Capacitor plugins from `package.json`, and (3) updates `project.pbxproj` to reference CocoaPods instead of SPM.

**File**: `ios/App/Podfile` (new, generated), `ios/App/App.xcodeproj/project.pbxproj` (modified)

**Pattern**:
```bash
# Build the Angular app first (cap sync copies the build output)
cd {WORKSPACE}
npm run build -- --configuration production

# Sync Capacitor — generates Podfile and updates pbxproj
npx cap sync ios
```

The generated `Podfile` will look similar to the howDays reference pattern:
```ruby
require_relative '../../node_modules/@capacitor/ios/scripts/pods_helpers'

platform :ios, '16.0'
use_frameworks!

# workaround to avoid Xcode caching of Pods
install! 'cocoapods', :disable_input_output_paths => true

def capacitor_pods
  pod 'Capacitor', :path => '../../node_modules/@capacitor/ios'
  pod 'CapacitorCordova', :path => '../../node_modules/@capacitor/ios'
  # Each installed @capacitor/* and @capacitor-community/* plugin
  # appears here as a pod entry auto-generated by cap sync
end

target 'App' do
  capacitor_pods
  # Additional pods not managed by Capacitor can be added here
end
```

**Verify**: `cat ios/App/Podfile` — confirm it lists Capacitor core and all installed plugins. Cross-check plugin count against `package.json` Capacitor dependencies.

### Step 5: Install CocoaPods dependencies

**Action**: Run `pod install` inside the `ios/App/` directory to resolve and download all pod dependencies. This creates `Podfile.lock` and the `App.xcworkspace`.

**File**: `ios/App/Podfile.lock` (new, generated), `ios/App/App.xcworkspace/` (new, generated), `ios/App/Pods/` (new, generated — gitignored)

**Pattern**:
```bash
cd {WORKSPACE}/ios/App
pod install
```

Expected output includes lines like:
```
Installing Capacitor (7.x.x)
Installing CapacitorCordova (7.x.x)
Installing CapacitorCamera (7.x.x)
Installing CapacitorHaptics (7.x.x)
...
Pod installation complete! N dependencies from the Podfile are installed in X pods.
```

**Verify**: `ls ios/App/Podfile.lock ios/App/App.xcworkspace/contents.xcworkspacedata` — both must exist. `pod install` exit code must be 0.

### Step 6: Update .gitignore

**Action**: Add `ios/App/Pods/` to `.gitignore`. The `Pods/` directory contains vendored source code that is fully reproducible from `Podfile.lock` via `pod install`. Convention: commit `Podfile` and `Podfile.lock`, ignore `Pods/`.

**File**: `.gitignore`

**Pattern**:
```gitignore
# CocoaPods vendored dependencies (reproduced via pod install)
ios/App/Pods/
```

**Verify**: `grep "Pods" .gitignore` — expect the line `ios/App/Pods/`.

### Step 7: Verify Xcode build

**Action**: Build the project using the `.xcworkspace` (not `.xcodeproj`) to confirm all dependencies resolve and the app compiles.

**File**: n/a (build verification)

**Pattern**:
```bash
cd {WORKSPACE}/ios/App
xcodebuild \
  -workspace App.xcworkspace \
  -scheme App \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  build \
  2>&1 | tail -20
```

**Verify**: Exit code 0 and output includes `** BUILD SUCCEEDED **`. If the build fails, check:
1. SPM references still in `project.pbxproj` → go back to Step 2 and remove manually
2. Pod version conflicts → run `pod update` and retry
3. Missing plugin podspec → verify the npm package is installed (`npm ls @capacitor/...`)

### Step 8: Verify simulator launch

**Action**: Boot the app on an iOS Simulator to confirm it renders the Angular web view and doesn't crash on native plugin initialization.

**File**: n/a (runtime verification)

**Pattern**:
```bash
cd {WORKSPACE}/ios/App
xcodebuild \
  -workspace App.xcworkspace \
  -scheme App \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  build
# Then launch via Xcode or:
xcrun simctl boot "iPhone 16" 2>/dev/null || true
xcrun simctl install booted {WORKSPACE}/ios/App/build/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch booted com.bubls.app
```

Alternatively, open the workspace in Xcode and run:
```bash
npx cap open ios   # Opens App.xcworkspace in Xcode
# Press Cmd+R to build and run on simulator
```

**Verify**: The app launches on the simulator without crashing. The Angular web view renders (even if content is placeholder). Console output does not show `fatal error` or `dylib not loaded` related to plugin pods.

## 5. Tests

This task is a build-system migration with no runtime code changes. There are no unit tests to write. Verification is build-and-launch (Steps 7–8 above).

However, add a **structural check script** to prevent SPM from being reintroduced:

```bash
# scripts/check-no-spm.sh (new)
#!/bin/bash
# Structural check: SPM must not exist alongside CocoaPods.
# Run in CI to prevent accidental reintroduction.

ERRORS=0

if [ -f "ios/App/Package.swift" ]; then
  echo "FAIL: ios/App/Package.swift exists — SPM must not coexist with CocoaPods"
  ERRORS=$((ERRORS + 1))
fi

if [ -f "ios/App/Package.resolved" ]; then
  echo "FAIL: ios/App/Package.resolved exists — SPM lock file must be removed"
  ERRORS=$((ERRORS + 1))
fi

SPM_REFS=$(grep -c "XCRemoteSwiftPackageReference\|XCSwiftPackageProductDependency" ios/App/App.xcodeproj/project.pbxproj 2>/dev/null || echo "0")
if [ "$SPM_REFS" -gt 0 ]; then
  echo "FAIL: project.pbxproj contains $SPM_REFS SPM references — remove all XCRemoteSwiftPackageReference and XCSwiftPackageProductDependency entries"
  ERRORS=$((ERRORS + 1))
fi

if [ ! -f "ios/App/Podfile" ]; then
  echo "FAIL: ios/App/Podfile missing — CocoaPods is the required dependency manager"
  ERRORS=$((ERRORS + 1))
fi

if [ ! -f "ios/App/Podfile.lock" ]; then
  echo "FAIL: ios/App/Podfile.lock missing — must be committed for reproducible builds"
  ERRORS=$((ERRORS + 1))
fi

if [ "$ERRORS" -eq 0 ]; then
  echo "OK: CocoaPods is the sole dependency manager, no SPM artifacts detected"
fi

exit $ERRORS
```

**Assertion**: `bash scripts/check-no-spm.sh` exits with code 0 and prints `OK: CocoaPods is the sole dependency manager, no SPM artifacts detected`.

## 8. Rollback

- **Per-step**: each commit is independently revertible. `git revert <sha>`.
  - Reverting commit 2 (CocoaPods files) without reverting commit 1 (SPM removal) will leave the project without any dependency manager — if rolling back, revert both commits in reverse order.
- **Per-branch**: if verification fails catastrophically, `git reset --hard <pre-task-sha>` restores the original SPM-based state. The `ios/App/Pods/` directory (gitignored) should be deleted manually: `rm -rf ios/App/Pods/`.
- **CocoaPods artifacts**: `pod deintegrate` inside `ios/App/` removes all CocoaPods integration from the Xcode project, restoring it to a pre-`pod install` state.

## 9. Deviations Allowed

- **`Package.swift` or `Package.resolved` doesn't exist** — the project may already lack SPM files (e.g., if a prior attempt partially cleaned them). Skip Step 1, note deviation in commit body, proceed to Step 3.
- **`cap sync` doesn't generate a Podfile** — Capacitor version may require `--deployment` flag or a manual `npx cap init` step. Check `npx cap doctor` output and consult Capacitor 7 docs. If the Podfile must be hand-written, port the structure from howDays' `ios/App/Podfile` verbatim and list each plugin pod manually. Log as a deviation.
- **`pod install` fails on a specific plugin** — one or more community plugins may not have a published podspec for the installed npm version. Pin the working version in `Podfile` (e.g., `pod 'CapacitorCommunitySpeechRecognition', '7.0.0'`) and log the version pin as a deviation.
- **`xcodebuild` fails with signing errors** — simulator builds should not require signing. If the scheme requires a team, add `CODE_SIGNING_ALLOWED=NO` to the `xcodebuild` invocation. If the scheme name differs from `App`, check with `xcodebuild -workspace App.xcworkspace -list` and use the correct scheme. Log deviation.
- **SPM entries in `project.pbxproj` persist after `cap sync`** — remove manually by editing the file. Search for `XCRemoteSwiftPackageReference`, `XCSwiftPackageProductDependency`, and `packageReferences` blocks and delete them. Log the manual edit in the commit body.
- **Existing `Podfile` found** — if `ios/App/Podfile` already exists (from a prior partial migration), delete it before running `cap sync` so Capacitor generates a clean one. Log deviation.

## 10. Out of Scope

This task migrates the dependency manager and verifies the build. It does not add, remove, or configure any Capacitor plugins — that verification is Task 2's responsibility. It does not update CI/CD workflows to use `pod install` or `.xcworkspace` — that is Task 6. It does not create any Angular/TypeScript adapter services or shared modules — those are Tasks 3–5.

- **Plugin verification** — confirming each plugin (speech recognition, media, camera, RevenueCat) actually works at runtime is Task 2. This task only proves the build succeeds.
- **CI/CD pipeline update** — adding `pod install` to GitHub Actions, caching `Pods/`, and switching from `-project` to `-workspace` in Fastlane is Task 6.
- **`capacitor.config.ts` plugin configuration** — no plugin config changes are needed for the dependency manager swap. Plugin-specific config (SQLite, RevenueCat, live-update) is deferred to Tasks 3–5.
- **Android** — Bubls is iOS-first. No Android build changes.
- **CocoaPods version pinning strategy** — whether to use exact versions, optimistic operators, or unpinned pods in the Podfile is a decision for after Task 2 reveals which plugins have version-sensitive behavior. For now, accept whatever `cap sync` generates.

**Rule for the executor**: if a change appears helpful but is listed here, STOP and flag it as a deviation rather than expanding this task's blast radius.
