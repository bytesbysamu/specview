## Implementation Steps

### Step 1: Create the `bubls_subscribers` table

**File**: `worker/schema.sql` (append) or `pipeline/sql/002_create_subscribers.sql`

**Purpose**: Store subscriber identity and preferences. This is the table that Task 3's curation pipeline reads to determine which interests to use for vector similarity queries.

```sql
CREATE TABLE IF NOT EXISTS bubls_subscribers (
    id              SERIAL PRIMARY KEY,
    email           TEXT NOT NULL UNIQUE,
    city            TEXT NOT NULL DEFAULT 'zurich',
    interests       TEXT[] NOT NULL DEFAULT '{}',
    token           UUID NOT NULL DEFAULT gen_random_uuid(),
    active          BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_subscribers_token
    ON bubls_subscribers(token);

CREATE INDEX IF NOT EXISTS idx_subscribers_active
    ON bubls_subscribers(active)
    WHERE active = TRUE;
```

Run against Neon:
```bash
psql "$DATABASE_URL" -f pipeline/sql/002_create_subscribers.sql
```

Key decisions:
- `email` is unique — one subscriber per email, no duplicate accounts
- `interests` is `TEXT[]` not a junction table — with 8 fixed categories, an array is simpler to query (`@>` operator) and update than a many-to-many relationship
- `token` is a UUID generated by Postgres, not the application — no crypto dependency, no collision risk at this scale
- No `password` column, no `session` table — magic link tokens are the entire auth model

### Step 2: Add subscriber API endpoints to Express proxy

**File**: `server.js` (extend existing Express server from Task 2)

**Purpose**: Three endpoints that the Angular client calls: create subscriber, fetch subscriber by token, update interests. No middleware, no auth framework — the token in the request IS the identity.

**Pattern**:
```javascript
// POST /api/subscribers — Create new subscriber (onboarding)
app.post('/api/subscribers', async (req, res) => {
  const { email, city, interests } = req.body;

  const ALLOWED_INTERESTS = ['music', 'food', 'outdoors', 'art', 'nightlife', 'tech', 'sports', 'family'];
  const validInterests = interests.filter(i => ALLOWED_INTERESTS.includes(i));

  if (!email || validInterests.length === 0 || validInterests.length > 3) {
    return res.status(400).json({ error: 'Email and 1-3 valid interests required' });
  }

  const result = await pool.query(
    `INSERT INTO bubls_subscribers (email, city, interests)
     VALUES ($1, $2, $3)
     ON CONFLICT (email) DO UPDATE SET
       interests = $3, city = $2, active = TRUE, updated_at = NOW()
     RETURNING id, token, email, city, interests`,
    [email, city || 'zurich', validInterests]
  );
  res.json(result.rows[0]);
});

// GET /api/subscribers/:token — Fetch subscriber by magic link token
app.get('/api/subscribers/:token', async (req, res) => {
  const result = await pool.query(
    'SELECT id, email, city, interests, created_at FROM bubls_subscribers WHERE token = $1 AND active = TRUE',
    [req.params.token]
  );
  if (result.rows.length === 0) return res.status(404).json({ error: 'Subscriber not found' });
  res.json(result.rows[0]);
});

// PATCH /api/subscribers/:token/interests — Update interests
app.patch('/api/subscribers/:token/interests', async (req, res) => {
  const { interests } = req.body;
  const ALLOWED_INTERESTS = ['music', 'food', 'outdoors', 'art', 'nightlife', 'tech', 'sports', 'family'];
  const validInterests = interests.filter(i => ALLOWED_INTERESTS.includes(i));

  if (validInterests.length === 0 || validInterests.length > 3) {
    return res.status(400).json({ error: '1-3 valid interests required' });
  }

  const result = await pool.query(
    `UPDATE bubls_subscribers SET interests = $1, updated_at = NOW()
     WHERE token = $2 AND active = TRUE RETURNING id, email, interests`,
    [validInterests, req.params.token]
  );
  if (result.rows.length === 0) return res.status(404).json({ error: 'Subscriber not found' });
  res.json(result.rows[0]);
});
```

Key decisions:
- `ON CONFLICT (email) DO UPDATE` — re-signup updates interests instead of erroring
- Token returned only on create — client stores in localStorage, subsequent requests use token in URL path
- Interest validation server-side — never trust the client

### Step 3: Create the SubscriberService

**File**: `src/app/services/subscriber.service.ts`

**Purpose**: Thin HTTP wrapper for the subscriber API. Handles token persistence in localStorage so return visitors skip onboarding.

**Pattern**:
```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, tap } from 'rxjs';
import { environment } from '../../environments/environment';

export interface Subscriber {
  id: number;
  email: string;
  city: string;
  interests: string[];
  token?: string;
  created_at?: string;
}

const TOKEN_KEY = 'bubls_token';

@Injectable({ providedIn: 'root' })
export class SubscriberService {
  private http = inject(HttpClient);
  private apiUrl = `${environment.apiUrl}/api/subscribers`;

  signup(email: string, city: string, interests: string[]): Observable<Subscriber> {
    return this.http.post<Subscriber>(this.apiUrl, { email, city, interests }).pipe(
      tap(sub => { if (sub.token) localStorage.setItem(TOKEN_KEY, sub.token); })
    );
  }

  getSubscriber(): Observable<Subscriber> {
    return this.http.get<Subscriber>(`${this.apiUrl}/${this.getToken()}`);
  }

  updateInterests(interests: string[]): Observable<Subscriber> {
    return this.http.patch<Subscriber>(`${this.apiUrl}/${this.getToken()}/interests`, { interests });
  }

  hasToken(): boolean { return !!localStorage.getItem(TOKEN_KEY); }
  getToken(): string | null { return localStorage.getItem(TOKEN_KEY); }
  clearToken(): void { localStorage.removeItem(TOKEN_KEY); }
}
```

- Token in `localStorage` (not cookies) — Capacitor handles this identically on iOS and web
- `hasToken()` is the onboarding gate
- Invalid tokens get a 404, which triggers re-onboarding

  initial = input<string[]>([]);
  selectionChange = output<string[]>();

**Pattern**:
```typescript
import { Routes } from '@angular/router';
import { inject } from '@angular/core';
import { Router } from '@angular/router';
import { SubscriberService } from './services/subscriber.service';

const dashboardGuard = () => {
  const sub = inject(SubscriberService);
  if (!sub.hasToken()) return inject(Router).createUrlTree(['/onboarding']);
  return true;
};

export const routes: Routes = [
  {
    path: 'onboarding',
    loadComponent: () => import('./pages/onboarding/onboarding.page').then(m => m.OnboardingPage),
    canActivate: [() => !inject(SubscriberService).hasToken()]
  },
  {
    path: 'dashboard',
    loadComponent: () => import('./pages/dashboard/picks-dashboard.page').then(m => m.PicksDashboardPage),
    canActivate: [() => dashboardGuard()]
  },
  { path: '', redirectTo: 'dashboard', pathMatch: 'full' }
];
```

Default route → dashboard → guard redirects to onboarding if no token. Deep links like `/dashboard?token=uuid` from magic link emails work without additional routing.

// Countdown to next Thursday 6pm
private getNextThursday(): Date {
  const now = new Date();
  const daysUntilThursday = (4 - now.getDay() + 7) % 7 || 7;
  const next = new Date(now);
  next.setDate(now.getDate() + daysUntilThursday);
  next.setHours(18, 0, 0, 0);
  return next;
}

## Edge Cases to Handle

| Scenario | Behavior |
|----------|----------|
| Same email signs up twice | Upsert updates interests and reactivates — no error, no duplicate |
| Token in URL but invalid | Server 404 → client clears stored token → redirect to onboarding |
| User selects 0 interests | "Continue" button disabled. Server returns 400 if bypassed |
| User changes interests after receiving picks | Next Thursday uses updated interests. Existing picks unaffected |
| localStorage unavailable | Capacitor web view supports it. Safari private browsing does too since iOS 11 |
