# 🛠️ Task 7: /text route + text operations UI

**Purpose**: Ship a user-facing `/text` tab (textarea + 5 rewrite modes + generate) backed by `POST /api/text/rewrite` and `POST /api/text/generate`, both routed through `chain.adapter.generate` — proving the primitive generalises beyond photoshoot with a second consumer.

**Effort**: 1 day

**Dependencies**: Task 1 (`superapp_users.builder` / `principles` columns), Task 2 (`server/modules/chain/` adapter + runner)

**Parallel With**: Task 6 (photoshoot retrofit) — both consume the chain primitive independently; if their shapes diverge, one is wrong.

**Blocks**: Nothing downstream in the current epic. Provides the reference shape Task 6 reconciles against.

**Related**:
- [Solution Architecture](./architecture.md)
- [Epic](./epic.md)

## 1. Context

Task 7 delivers the second consumer of the chain primitive. Photoshoot retrofit (Task 6) is the first consumer; `/text` is the reference case. Backend ships a tiny Flask blueprint with two routes (`rewrite` and `generate`) and five prompt one-liners. The persistence model is an opt-in extension of `superapp_generations` — a nullable `feature` discriminator (`"photoshoot" | "text"`) and a nullable `input_text`, with `result_image_url` relaxed to nullable. One unified generations table so future features extend the same row shape instead of forking a new table per feature. Frontend is a single standalone Angular page under `src/app/pages/text/` with an adapter service and a TestBed spec. The `humanize` mode ports the REWRITE_PROMPT from `humanize-me/backend/app.py`; the other four modes are fresh one-liners. A structural test mirrors Task 2's boundary grep: any `server/modules/text/**` file that imports from `chain.providers.*` fails CI.

**Trade-offs considered**:
- **Two generation tables (text_generations + photoshoot_generations)** — rejected because every new feature would fork another table; namespace via a `feature` column instead and keep `superapp_generations` unified.
- **Streaming SSE for rewrite** — rejected for v1; batch `generate` over JSON matches humanize-me's heavy-mode pattern, keeps the frontend trivial, and defers SSE plumbing until a user complains about perceived latency.
- **Default-on feature flag** — rejected because the epic explicitly says opt-in; no bulk update of `enabled_features`. Users get `/text` when their row flips the flag, not before.

```python
from server.modules.chain import adapter
from . import prompts, repository

def rewrite(user, text: str, mode: str, session) -> dict:
    if mode not in prompts.MODES:
        raise ValueError(f"unknown mode {mode!r}")
    result = adapter.generate(
        system=prompts.MODES[mode],
        prompt=text,
        user=user,
        feature="text",
    )
    row = repository.create_text_generation(
        session, user_id=user.id, mode=mode, input_text=text, output=result.text,
    )
    return {"id": str(row.id), "mode": mode, "output": result.text}
```

```python
from flask import Blueprint, g, jsonify, request
from server.core.auth import require_auth  # match photoshoot's import
from server.core.db import get_session     # match photoshoot's session helper
from . import service

bp = Blueprint("text", __name__, url_prefix="/api/text")


@bp.post("/rewrite")
@require_auth
def rewrite():
    data = request.get_json(silent=True) or {}
    text, mode = data.get("text"), data.get("mode")
    if not text or not mode:
        return jsonify({"error": "text and mode required"}), 400
    try:
        with get_session() as session:
            return jsonify(service.rewrite(g.current_user, text, mode, session))
    except ValueError as e:
        return jsonify({"error": str(e)}), 400


@bp.post("/generate")
@require_auth
def generate():
    data = request.get_json(silent=True) or {}
    prompt = data.get("prompt")
    if not prompt:
        return jsonify({"error": "prompt required"}), 400
    with get_session() as session:
        return jsonify(service.generate(g.current_user, prompt, session))
```

```typescript
@Component({
  selector: 'app-text',
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [IonicModule, FormsModule],
  templateUrl: './text.page.html',
  styleUrl: './text.page.scss',
})
export class TextPage {
  private api = inject(TextApiService);
  text = signal('');
  mode = signal<Mode>('humanize');
  result = signal<string | null>(null);
  loading = signal(false);
  error = signal<string | null>(null);
  canSubmit = computed(() => this.text().trim().length > 0 && !this.loading());

  submit() {
    this.loading.set(true); this.error.set(null);
    this.api.rewrite(this.text(), this.mode()).subscribe({
      next: r => { this.result.set(r.output); this.loading.set(false); },
      error: e => { this.error.set('Rewrite failed'); this.loading.set(false); },
    });
  }
}
```

## 10. Out of Scope

This task ships the `/text` feature as a second chain consumer. It does NOT ship streaming, heavy-mode multi-pass, usage limits, or a unified generations history page. The point is to prove the primitive generalises — not to build a full text product.

- **SSE streaming for `/rewrite` or `/generate`** — batch JSON is enough for day one; defer until user feedback demands progressive rendering.
- **Heavy-mode 3-pass humanization** (from `humanize-me/backend/services/humanizer.py`) — v1 is single-pass; multi-pass lands only when a user asks for it.
- **Usage limits / rate limiting / paywall** — mimic later via a separate `usage` table; this task does not write limit logic.
- **Unified generation history UI** (list of all `superapp_generations` rows filtered by `feature`) — nice to have, not load-bearing for v1.
- **Mass-flip of `enabled_features` to include `"text"` for existing users** — opt-in per epic. No bulk migration.
- **Prompt A/B testing infrastructure** — five fixed prompts; iterate by editing the constants when user feedback arrives.
- **`chain_call` / `chain_signal` persistence** — still deferred per Task 2. Do not reintroduce.
- **Declarative `ChainDefinition` types for multi-step text chains** — `/text` is a single adapter call; no chain composition required. Do not build it.
- **Reconciling Task 6's photoshoot retrofit with this module** — if shapes diverge, flag in the Task 6 retrospective; do not edit `photoshoot/service.py` from inside Task 7.
- **Native iOS tab placement / Capacitor shell changes** — `/text` is a web-first route registered via the feature registry; native polish is a follow-up.

**Rule for the executor**: if a change appears helpful but is listed here, STOP and flag it as a deviation rather than expanding this task's blast radius.
