# Task 2: iOS Permission Setup + Capacitor Config

**Purpose**: Install the `@capacitor-community/speech-recognition` Capacitor plugin, configure iOS permission strings, and sync the native project so subsequent voice-input tasks (adapter service, mic button) have a working plugin to code against.

**Effort**: 0.5 day

## 1. Context

This task wires the `@capacitor-community/speech-recognition` Capacitor plugin into the Bubls iOS project. The plugin wraps Apple's `SFSpeechRecognizer` for on-device speech-to-text — zero API cost, offline-capable, supports 60+ languages. iOS requires two permission strings in `Info.plist` before the system will present permission dialogs: one for speech recognition (`NSSpeechRecognitionUsageDescription`) and one for microphone access (`NSMicrophoneUsageDescription`). Without these entries, the app crashes on first `SFSpeechRecognizer` call. Capacitor 7 auto-discovers plugins via CocoaPods, so no explicit plugin registration code is needed — but `npx cap sync ios` must run after install to regenerate the Podfile and native project references. This task is deliberately isolated from the service/UI work so it can be verified independently (plugin initializes, permissions prompt appears, no crash).

**Trade-offs considered**:
- **Add permissions via `capacitor.config.ts` plugin config** — rejected because `@capacitor-community/speech-recognition` does not support `ios.permissionDescriptions` config; Info.plist entries are the standard Capacitor/iOS mechanism for permission strings.
- **Defer `cap sync` to a later task** — rejected because plugin availability on the native side is the gating prerequisite for device testing and the adapter's real provider path. Shipping the sync now unblocks the entire voice-input chain.
- **Install and configure in `package.json` only, let CI handle `cap sync`** — preferred approach is to run `cap sync ios` locally during this task so the executor can verify the Podfile generation and simulator launch immediately, catching integration issues before any code is written against the plugin.

## 4. Implementation Steps

### Step 1: Install the speech-recognition plugin

**Action**: Add `@capacitor-community/speech-recognition` as a production dependency. Use the latest version compatible with Capacitor 7.

**File**: `package.json`

**Pattern**:
```bash
npm install @capacitor-community/speech-recognition@latest
```

After install, verify it appears in `package.json` under `dependencies`:
```json
{
  "dependencies": {
    "@capacitor-community/speech-recognition": "^7.0.0"
  }
}
```

**Verify**: `cat package.json | grep speech-recognition` — expect a line showing the dependency with a version number. If the plugin's latest major does not match Capacitor 7 (i.e., the plugin publishes `^6.x` as latest), install `@capacitor-community/speech-recognition@next` or pin the Capacitor-7-compatible version explicitly. Check the plugin's npm page or GitHub releases for the correct version. If no Capacitor-7-compatible version exists, STOP and flag as a deviation — the entire voice-input feature depends on this plugin.

### Step 2: Add iOS permission strings to Info.plist

**Action**: Add `NSSpeechRecognitionUsageDescription` and `NSMicrophoneUsageDescription` entries to the iOS Info.plist. These are the rationale strings iOS displays in the system permission dialog.

**File**: `ios/App/App/Info.plist`

**Pattern**: Add the following two key-string pairs inside the top-level `<dict>` block, alongside existing permission entries (e.g., near `NSCameraUsageDescription` if it exists):

```xml
<key>NSSpeechRecognitionUsageDescription</key>
<string>Bubls uses speech recognition to transcribe your voice into text for rewriting</string>
<key>NSMicrophoneUsageDescription</key>
<string>Bubls needs microphone access to hear your voice for transcription</string>
```

**Placement**: Insert AFTER the last existing `NS*UsageDescription` entry in the file if any exist. If none exist, insert before the closing `</dict>` tag. Do NOT place inside a nested dict — these must be top-level children of the root `<dict>`.

**Verify**: `grep -c "NSSpeechRecognitionUsageDescription\|NSMicrophoneUsageDescription" ios/App/App/Info.plist` — expect `2`. Also verify well-formed XML: `plutil -lint ios/App/App/Info.plist` — expect `ios/App/App/Info.plist: OK`.

### Step 3: Add plugin configuration to capacitor.config.ts

**Action**: Add a `SpeechRecognition` entry under the `plugins` key in `capacitor.config.ts`. This sets the default recognition language. Capacitor 7 auto-discovers the plugin via CocoaPods — no manual registration is needed.

**File**: `capacitor.config.ts`

**Pattern**: If the file already has a `plugins` block, add `SpeechRecognition` to it. If it has no `plugins` block, add one.

```typescript
const config: CapacitorConfig = {
  // ... existing appId, appName, webDir, etc.
  plugins: {
    // ... existing plugin configs (if any)
    SpeechRecognition: {
      language: 'en-US',
    },
  },
};
```

**Important**: Do NOT remove or reorder existing plugin configs. Only add the `SpeechRecognition` entry. If `plugins` already exists as a key, extend the object. If it does not exist, add it as a new key on the config object.

**Verify**: `grep -A2 "SpeechRecognition" capacitor.config.ts` — expect to see the language config. TypeScript compilation: `npx tsc --noEmit capacitor.config.ts` or `npx cap doctor` — expect no errors.

### Step 4: Sync the native iOS project

**Action**: Run `npx cap sync ios` to regenerate the Podfile, install CocoaPods dependencies, and copy the web build to the native project.

**File**: No file edited directly — this command modifies `ios/App/Podfile`, `ios/App/Podfile.lock`, and `ios/App/Pods/`.

**Pattern**:
```bash
# Build the Angular project first (cap sync copies www/ into the native project)
npm run build

# Sync Capacitor — installs plugin pods, copies web assets
npx cap sync ios
```

**Verify**: Check three things:
1. `grep "speech-recognition" ios/App/Podfile` (or `grep -i "speechrecognition" ios/App/Podfile`) — expect the plugin listed as a Pod dependency
2. `npx cap doctor` — expect no errors for the iOS platform
3. Exit code of `npx cap sync ios` is 0

**Note**: If `npx cap sync ios` fails with a CocoaPods error, try:
```bash
cd ios/App && pod install --repo-update && cd ../..
```
If that also fails, check that CocoaPods is installed (`gem install cocoapods` or `brew install cocoapods`). Flag as a deviation if the dev environment doesn't have CocoaPods — this is a macOS/Xcode prerequisite.

### Step 5: Verify plugin initialization on simulator [REQUIRES APPROVAL — launches simulator]

**Action**: Open the iOS project in Xcode and run on a simulator to verify the plugin loads without crash.

**File**: N/A — this is a manual verification step.

**Pattern**:
```bash
# Open in Xcode
npx cap open ios

# In Xcode: select an iPhone 15 Pro simulator, press Cmd+R to run
# Expected: app launches to the normal screen without crash
# Check Xcode console: no "plugin not found" or "unrecognized selector" errors
```

**Verify**: App launches on simulator without crash. Xcode console shows no errors related to `SpeechRecognition` or `SFSpeechRecognizer`. The plugin is loaded but NOT invoked yet — no permission dialog should appear (that's triggered by `requestPermission()` in Task 1's adapter code). Absence of crash is the success criterion.

**If verification cannot run** (no macOS/Xcode available in executor environment): log as a deviation in the commit body: `Deviations: simulator verification deferred — no Xcode in CI environment. Plugin installation verified via Podfile grep and cap doctor.` This is an acceptable deviation — the build-level verification in Step 4 catches most integration issues.

## 5. Tests

This task is pure configuration — no application code is written. Instead of unit tests, verification is structural: confirm the right dependencies and permission strings are in place.

Add the following to the project's existing structural/architecture test infrastructure. Match the repo's test framework — if `scripts/architecture-acl-check.mjs` uses Node.js `node:test` + `assert`, match that. If there's no existing infra test file, create `scripts/verify-ios-permissions.mjs` as a standalone script.

```javascript
// scripts/verify-ios-permissions.mjs
import { readFileSync } from 'node:fs';
import { test } from 'node:test';
import assert from 'node:assert/strict';

test('package.json includes @capacitor-community/speech-recognition', () => {
  const pkg = JSON.parse(readFileSync('package.json', 'utf8'));
  const dep = pkg.dependencies?.['@capacitor-community/speech-recognition']
           || pkg.devDependencies?.['@capacitor-community/speech-recognition'];
  assert.ok(dep, 'Missing @capacitor-community/speech-recognition in package.json dependencies');
});

test('Info.plist contains NSSpeechRecognitionUsageDescription', () => {
  const plist = readFileSync('ios/App/App/Info.plist', 'utf8');
  assert.ok(
    plist.includes('NSSpeechRecognitionUsageDescription'),
    'Info.plist missing NSSpeechRecognitionUsageDescription — iOS will crash on first speech recognition call'
  );
});

test('Info.plist contains NSMicrophoneUsageDescription', () => {
  const plist = readFileSync('ios/App/App/Info.plist', 'utf8');
  assert.ok(
    plist.includes('NSMicrophoneUsageDescription'),
    'Info.plist missing NSMicrophoneUsageDescription — iOS will crash on first microphone access'
  );
});

test('capacitor.config.ts configures SpeechRecognition plugin', () => {
  const config = readFileSync('capacitor.config.ts', 'utf8');
  assert.ok(
    config.includes('SpeechRecognition'),
    'capacitor.config.ts missing SpeechRecognition plugin config'
  );
});
```

Run with: `node --test scripts/verify-ios-permissions.mjs`

Expected: 4/4 passing.

## 10. Out of Scope

This task configures the plugin and permissions at the native project level. It does NOT write any TypeScript application code, create any Angular components, or invoke the plugin's API. The adapter service that actually calls `SpeechRecognition.start()` is Task 1. The mic button UI is Task 3. The text page integration is Task 4.

- **VoiceInputService adapter** — Task 1's scope. This task does not create `voice-input.service.ts` or any mock provider.
- **ACL banned-list update in `architecture-acl-check.mjs`** — ships with Task 1 when the adapter is created, because the ACL test validates that pages don't import the plugin directly (meaningless until the adapter exists).
- **Android permissions** — Android is not in scope for this epic (iOS-only App Store launch). If Android support is needed later, add `RECORD_AUDIO` permission to `AndroidManifest.xml` in a separate task.
- **Plugin API invocation or permission request flow** — calling `SpeechRecognition.requestPermission()` or `SpeechRecognition.start()` is Task 1 (adapter). This task only ensures the native prerequisites are in place.
- **Capacitor live-update or OTA config** — separate concern; not related to speech recognition.
- **CocoaPods → SPM migration** — per caveats, Bubls uses CocoaPods (not SPM). Do not attempt to migrate plugin management.

**Rule for the executor**: if a change appears helpful but is listed here, STOP and flag it as a deviation rather than expanding this task's blast radius.
